- `已使用`：代码或配置中已经存在，并有一定验证；
- `计划`：路线已考虑，但尚未实现；
- `候选`：需要进一步验证场景和方案；
- `不采用`：当前阶段明确不引入。

### 3.1 外部行情调用与密钥边界

真实行情供应商只能作为 Spring Boot 服务端的上游数据源。Vue/React 前端只能调用本项目的 Spring Boot API，不能直接调用 Longbridge 或其他供应商 API，也不能接收或保存 `APP_SECRET`、`ACCESS_TOKEN`、App Key 等供应商凭据。

```text
Longbridge / 其他供应商
          ↑  SDK、REST 或 WebSocket
          │
Vue/React ←→ Spring Boot
              ↑
          Redis / MySQL
```

凭据必须通过服务端环境变量、受保护的本机配置或部署平台密钥管理提供；不能进入前端源码、浏览器响应、日志、Git 或构建产物。Spring Boot 负责调用上游、校验返回值、记录来源和时间、写入缓存，再向前端返回经过项目接口约束的结果。供应商访问令牌泄漏可能影响关联账户，因此不得为了前端“方便调用”而下发凭据。

## 4. 当前明确不采用

| 技术/方案                           | 原因                                                                                                            |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Spring Cloud 微服务                 | 当前没有独立部署、扩缩容或团队边界                                                                              |
| Elasticsearch                       | A 股代码和名称搜索当前可由 MySQL 和索引满足                                                                     |
| Kubernetes                          | 个人项目当前没有多节点编排需求                                                                                  |
| 分库分表                            | 没有相应数据规模和容量证据                                                                                      |
| 完整元数据平台 / EAV / 动态表单引擎 | V1 的空间、股票、观点和研究周期结构明确；采用强类型业务字段与少量审计、来源元数据更容易约束、查询、测试和讲清楚 |
| AI 自动荐股                         | 偏离产品定位，并存在准确性、合规和风险问题                                                                      |
| Multi-Agent                         | 当前没有多个自主角色协作的真实必要性，单 Agent 工具闭环更易测试和解释                                           |
| Spring Modulith / ArchUnit          | 当前只采用按业务包组织和依赖方向规则，尚无边界失控证据，不增加结构校验依赖；需要自动检查模块依赖时再评估        |

## 5. 维护规则

当前目录采集辅助工具使用 Python 3.12、pandas/openpyxl 解析公开 JSON/Excel，并使用 `opencc-python-reimplemented==0.1.7` 批量繁简转换。仅作为本地目录准备工具，Java 继续负责校验、事务入库及 API 搜索；没有引入 Python 常驻服务或 AKShare 运行依赖。部署/复现方式见 [目录导入操作](../engineering/development.md#8-股票目录导入)。

- 新增、移除或升级技术后必须同步更新本文件。
- `package.json`、`pom.xml` 与本文件版本冲突时，以依赖清单为事实并修正文档。
- `计划` 和 `候选` 不能写进简历的“已实现技术栈”。
- 技术达到“已使用”至少需要代码或配置证据以及与风险匹配的验证结果。
