# BUG-007：图表卸载后迟到请求重新启动刷新

状态：2026-09-30 在 SPEC-003 UI-02 中修复。问题位于前端行情面板的异步生命周期，未修改研究事务、后端接口或行情供应商。

## 现象与复现

`StockMarketPanel` 在分时请求完成后启动 30 秒定时器，卸载时停止定时器并清理 Store。但停止已经存在的定时器，不能阻止一个尚未返回的请求之后再创建定时器。

定向组件测试复现两个场景：

- A 请求尚未完成时卸载 A，再打开 B 的分时图，最后返回 A 的响应。B 的共享分时数据标为 `updating`，旧 A 回调据此又启动刷新，测试观察到两个定时器，预期只有 B 的一个。
- 分时请求尚未完成时切回 K 线，之后响应返回。旧回调仍创建定时器，测试观察到一个定时器，预期为零。

测试用延迟 Promise 和虚拟时间精确控制顺序，不等待真实 30 秒，也不访问真实供应商。初版测试的简化数据缺少 `points`，修正测试数据后才取得上述生命周期失败断言；测试数据错误不属于产品缺陷。

## 根因与修复

组件清理和异步回调是两条执行路径。`onBeforeUnmount` 清理发生后，请求的 `await` 仍可能恢复执行。Store 的请求版本已经保护数据回填，但面板自己的日期、错误导航和定时器还需要单独保护。

修复给分时请求增加版本号，在返回、创建定时器及继续调度时检查版本、卸载状态和当前图表模式。切回 K 线、卸载或更换股票使旧分时请求失效；切回 K 线同时清理分时 Store。调度函数先核对版本，再停止当前定时器，防止旧刷新完成后误清掉新一轮的定时器。更换股票参数时重新读取新目标；K 线及更早历史的错误处理也核对当前目标是否有效。

共享自选继续只有一个活动面板。切到另一张股票卡片时，先清空展开 ID，等待 Vue 的 `nextTick` 完成旧面板卸载，再挂新面板，避免列表更新顺序使旧面板清理新面板的数据。快速切换通过切换版本保留最后一次选择。

UI-02 同时补充关注级别写入的页面退出保护：服务器已处理的写入仍有效，但离页之后的旧完成回调不能再加载旧空间列表、回填错误或清除新操作状态。这不改变服务器写入结果，也不声称取消已经发出的 HTTP 请求。

## 验证与边界

`stock-market-panel.spec.ts` 覆盖迟到响应、切回 K 线、同组件股票参数复用、后台隐藏时不读行情、卸载后停止轮询，以及旧刷新完成不能清掉新定时器。`stock-store.spec.ts` 覆盖离页后关注级别写入的成功与失败回调隔离。

真实 test 后端与 MySQL 的 UI-02 浏览器脚本验证双向切换、始终单面板、收起卸载、A 的 K 线响应迟到后 B 仍可显示，以及分时／K 线模式切换。独立行情页和研究详情继续使用同一组件，通过目录与 auth smoke 复核兼容。完整命令结果及清理证据见 [SPEC-003 UI-02](../../specs/003-ui-migration/tasks.md#ui-02-正式迁移2026-09-30)。本轮没有进行真实行情盘中或生产部署验收。
