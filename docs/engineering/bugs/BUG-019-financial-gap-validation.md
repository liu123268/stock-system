# BUG-019：资料缺口成为财务数字校验的旁路

2026-10-21。影响新生成且最终段落带财务引用的追问答案，来源为代码审查和离线复现；没有证据表明真实模型曾输出本次自造坏例子，不改写旧真实题集的结论。

## 现象与根因

`ResearchReply` 同时包含正文段落和 `missingInformation`。旧 `parseReply` 对每段带财务引用的正文调用数值保护，但对缺口只检查非空、数量与长度；页面仍会展示并保存这两类文字。

在真实工具循环中替换最后的模型回复，保持正文和财务引用合法，只把错误数字放入缺口：虚构亿元换算、同一金额改成万元、同比遗漏百分号、把元数据年份写成百分比。修复前四个拒绝断言均失败，原因都是方法正常返回答案，说明这些输出实际通过了旧 Java 校验。它不是模型接口失败或 JSON 结构错误。

## 修复与范围

[ResearchQuestionService](../../../src/main/java/com/stock/system/agent/service/ResearchQuestionService.java) 的 v15 在正文与引用结构通过后，汇总最终段落实际引用的来源，对每条缺口调用相同的 [数字保护](../../../src/main/java/com/stock/system/agent/service/ResearchFinancialAnswerNumbers.java)。采用最终引用集合是为了与成功消息实际保存的来源依赖一致；没有使用本轮查询过但未引用的材料扩大授权。

缺口错误归入 `QUESTION_REPLY_FINANCIAL_GAPS`，保留原白名单规则和已发生用量，不保存错误答案，不自动发起修正模型请求。合法的缺失比较年份、原报单位及没有财务引用的纯报告回答仍按原边界处理，没有新增表或迁移。

这是数字字面和单位来源检查，不能证明“缺口是否相关”、科目和金额是否对应或其他自然语言含义。没有财务引用的回答不因此进入财务数字保护；历史消息不自动重新审核。原始合法年份的处理只见 [BUG-014](BUG-014-financial-missing-comparison-year.md)。

## 验证与预防

[ResearchFinancialQuestionTest](../../../src/test/java/com/stock/system/agent/ResearchFinancialQuestionTest.java) 保留四个坏例子，并检查阶段、规则、用量已知、诊断不含错误原文及只有计划内两次模型调用；正例保留缺少 2023 年比较列、原币／单位和报告单独说明。原拒绝测试失败日志与修复后定向回归、真实 Chrome 和清理证据只见 [任务第 34 节](../../specs/004-research-agent/tasks.md#34-财务答案缺口区域的数字校验2026-10-21)。

面试复述要点：外部模型的输出是未受信输入。响应的主要正文、缺口、提示等会展示的字段都要按其业务含义检查；只校验主字段会留下另一条错误数据进入保存与恢复链路的路径。JSON 合法、引用存在和事实受到依据支持是不同层次，不能用其中一项替代其他项。
