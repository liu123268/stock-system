# BUG-006：退出后的旧请求改变导航与会话

发现日期：2026-09-30，UI-01 实施浏览器验收。

## 现象与范围

刚进入空间概览便点击退出，清理本地会话并跳到公开首页后，尚未完成的加载链仍可能继续发送请求。浏览器实际停在 `/login?reason=expired`，使“退出回首页”断言失败。该现象来自现有异步加载与统一访问错误处理的协作，不是新配色导致的错误。

源码另确认空间详情已有请求版本保护，但列表、邀请码和成员读取原来会直接赋值；清缓存后的迟到响应可能重新填入旧数据。账号切换时，上一账号的错误响应也不能被当成新账号的会话失效。

## 根因与修复

`auth.logout()` 清空 Token 和用户，Layout 清空空间 Store；这不停止已经开始的 Promise。原 `handleWorkspaceApiError` 对收到的每个认证失败都执行清会话和跳转，没有区分请求开始时的账号与当前账号。类似地，直接赋值的 GET 完成后仍能更新已清空的 Store。

修复分两层：空间列表、邀请、成员读取保存请求版本，清理时递增版本；创建／加入额外保存会话版本，页面卸载后不再执行进入空间导航。HTTP 将请求的认证头与当前 Token 比较，只向 `ApiError` 添加旧会话布尔值，不保存或打印 Token；空间错误处理忽略旧会话响应和已经退出时的 401，当前有效会话收到的真实 401 仍正常清理并回登录。

这两层分别防止“旧响应回填状态”和“旧失败改变当前导航”，不是以忽略全部错误来修复。创建／加入的写入成功与刷新失败也分开：使用已保存的响应进入目标，不再次 POST。

## 验证与边界

单元测试在 `http-session.spec.ts` 验证认证头相同、切换及删除三种归属；`workspace-access.spec.ts` 同时保留当前会话 401 断言并增加退出／旧会话检查；`workspace-store.spec.ts` 验证迟到列表、邀请码和成员不得回填，以及保存成功后读取失败不能诱发重写。

真实 test 后端浏览器脚本 `ui-shell-smoke.mjs` 包含立即退出、换账号后释放旧 401、保存成功后 GET 失败，以及同组件更换空间参数／后退。实际完成证据只见 [UI-01 tasks](../../specs/003-ui-migration/tasks.md#ui-01-正式迁移2026-09-30)，数据及进程处理沿用 [测试规则](../testing.md)。没有因此宣称全部后续图表刷新或所有写操作竞态已经验证。

## UI-08 补充：认证与资料回调（2026-10-01）

认证 Store 的登录／资料响应原先直接存会话或用户，具有同一根因。UI-08 增加运行期 sessionVersion、登录请求失效与页面卸载检查；守卫在 me 验证返回后也检查会话，改密成功清理只作用于发起时仍存在的会话。具体数据流与前后端两个版本的区别只见 [认证设计](../../architecture/authentication.md#ui-08旧回调与当前会话)，不在此复制算法。

真实 Chrome 验证确认了另一个遗漏：后端已改密，成功响应仍被挂起，旧凭证读取空间列表得到 401，但选择页原 load 仅保留普通加载失败，没有清会话。现在该读取接入既有 handleWorkspaceApiError，并先检查卸载／当前会话。真实 401 清理仍保留，网络失败仍允许只读重试；创建／加入处理未在本块扩为全局重写。

新增单元测试保留原当前会话／401 断言，并覆盖迟到登录、me 成功／401、昵称与退出。浏览器把真实后端响应暂停后分别离页、换账号再释放，证明旧昵称不覆盖新管理员、旧登录不恢复会话、旧注册失败不改变导航、旧改密成功不退出新账号；正常改密及其他浏览器旧 JWT 拒绝也通过。证据见 [UI-08 tasks](../../specs/003-ui-migration/tasks.md#ui-08-正式迁移2026-10-01)。这些检查不撤销已提交事务，不代表任意设备吊销或所有 API 竞态都已验证。

## UI-09 补充：治理页面与共享状态（2026-10-01）

admin Store 原读取／状态响应会直接赋值，三页也没有约束卸载后的局部刷新和错误导航，属于同一“清缓存不能停止 Promise”根因。UI-09 用 Store lifetime／分资源版本保护数据，useAdminPage 用页面及会话归属保护提示、刷新与访问错误；写前旧 GET 和写后另选详情的边界也显式处理。算法只在 [治理数据流](../frontend.md#ui-09-中的治理目标保存结果与访问错误) 维护。

Store 测试覆盖五类迟到读取、两类迟到写入、详情切目标、旧错误、连点、写前 GET 和保存后读取失败。真实 Chrome 挂起用户详情后选另一用户、挂起已提交禁用后离页、退出并换账号再释放旧 401，均不污染新页／新会话；当前真实无效 JWT 的 401 仍清理，治理身份被撤销后的真实 FORBIDDEN 则刷新 me 并去普通入口。后端已提交事务不会因前端离页撤销。范围和证据见 [UI-09 tasks](../../specs/003-ui-migration/tasks.md#ui-09-正式迁移2026-10-01)，不称其覆盖所有业务 API。

## UI-01 补充：同账号离开空间选择页（2026-10-02）

复审实际复现了同账号的遗漏：创建 POST 尚未返回时进入既有归档空间，迟到创建成功把共享 currentWorkspace 改成新空间；选择页 disposed 阻止了导航，URL 仍指向归档空间，概览却变空。会话没有变化，所以原会话版本不能拦截它。该赋值逻辑迁移前已有；迁移后只保护导航，导致共享状态与路由不一致。

修复沿原版本机制增加选择页归属：卸载时使创建／加入回调及其列表读取失效，Store 不再覆盖后来的空间或发起旧刷新，页面也约束当前会话的导航与访问错误。服务器已经保存的事务仍然成立；正常留页时，写后列表读取失败仍进入保存响应中的空间。具体数据流只在 [前端说明](../frontend.md#十归档只读访问失效与退出登录) 维护。

Store 与组件测试分别覆盖迟到 POST、写后 GET 成功／失败、实际卸载、当前 401 及额外创建入口；原 shell smoke 增加真实 test 后端提交后挂起响应、进入归档空间再释放的创建／加入场景。所有测试和清理证据见 [复审修复任务](../../specs/003-ui-migration/tasks.md#2026-10-02迁移代码复审与修复已关闭)，不把这两个入口的保护解释成任意 API 都已验证。

## 复习与面试表达

清理 Store 是当前时刻的状态修改；异步任务的完成发生在之后。要避免账号或业务对象切换造成污染，需要检查请求版本／所属会话后再应用响应，还要约束导航、错误处理等副作用。组件 key 解决的是是否重建实例，无法单独阻止旧 Promise 完成。项目可用“退出后旧 401 把首页推到登录页”的具体复现说明二者区别，不声称前端检查代替服务端授权。
