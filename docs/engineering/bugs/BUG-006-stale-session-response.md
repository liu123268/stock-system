# BUG-006：退出后的旧请求改变导航与会话

发现日期：2026-09-30，UI-01 实施浏览器验收。

## 现象与范围

刚进入空间概览便点击退出，清理本地会话并跳到公开首页后，尚未完成的加载链仍可能继续发送请求。浏览器实际停在 `/login?reason=expired`，使“退出回首页”断言失败。该现象来自现有异步加载与统一访问错误处理的协作，不是新配色导致的错误。

源码另确认空间详情已有请求版本保护，但列表、邀请码和成员读取原来会直接赋值；清缓存后的迟到响应可能重新填入旧数据。账号切换时，上一账号的错误响应也不能被当成新账号的会话失效。

## 根因与修复

`auth.logout()` 清空 Token 和用户，Layout 清空空间 Store；这不停止已经开始的 Promise。原 `handleWorkspaceApiError` 对收到的每个认证失败都执行清会话和跳转，没有区分请求开始时的账号与当前账号。类似地，直接赋值的 GET 完成后仍能更新已清空的 Store。

修复分两层：空间列表、邀请、成员读取保存请求版本，清理时递增版本；创建／加入额外保存会话版本，页面卸载后不再执行进入空间导航。HTTP 将请求的认证头与当前 Token 比较，只向 `ApiError` 添加旧会话布尔值，不保存或打印 Token；空间错误处理忽略旧会话响应和已经退出时的 401，当前有效会话收到的真实 401 仍正常清理并回登录。

这两层分别防止“旧响应回填状态”和“旧失败改变当前导航”，不是以忽略全部错误来修复。创建／加入的写入成功与刷新失败也分开：使用已保存的响应进入目标，不再次 POST。

## 验证与边界

单元测试在 `http-session.spec.ts` 验证认证头相同、切换及删除三种归属；`workspace-access.spec.ts` 同时保留当前会话 401 断言并增加退出／旧会话检查；`workspace-store.spec.ts` 验证迟到列表、邀请码和成员不得回填，以及保存成功后读取失败不能诱发重写。

真实 test 后端浏览器脚本 `ui-shell-smoke.mjs` 包含立即退出、换账号后释放旧 401、保存成功后 GET 失败，以及同组件更换空间参数／后退。实际完成证据只见 [UI-01 tasks](../../specs/003-ui-migration/tasks.md#ui-01-正式迁移2026-09-30)，数据及进程处理沿用 [测试规则](../testing.md)。没有因此宣称全部后续图表刷新或所有写操作竞态已经验证。

## 复习与面试表达

清理 Store 是当前时刻的状态修改；异步任务的完成发生在之后。要避免账号或业务对象切换造成污染，需要检查请求版本／所属会话后再应用响应，还要约束导航、错误处理等副作用。组件 key 解决的是是否重建实例，无法单独阻止旧 Promise 完成。项目可用“退出后旧 401 把首页推到登录页”的具体复现说明二者区别，不声称前端检查代替服务端授权。
