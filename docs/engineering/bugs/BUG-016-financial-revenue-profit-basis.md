# BUG-016：金额正确但把收入统称为归母口径

2026-10-21。作用于研究助手的财务追问文字说明，不改变财务来源、Java 比较值或全局账号规则。

## 真实现象与定位

当前版本的完整真实验收在腾讯原年度题第一份回答就停止。模型正确返回收入 751766、股东应占盈利 224842、原报人民币百万元及两项同比，但写出“**两项均属于归母口径，其中收入不适用利润口径**”。这句话前后矛盾：实际收入的 profitBasis=NOT_APPLICABLE，只有净利润为 PARENT_SHAREHOLDERS。

原始结果在 target/agent-closure-real-20261021-100018-c0362a47/results.json，版本为 research-question-20261018-v11-missing-comparison-year。程序／工具通过 1／14，四维语义未通过，后十三次没有派发；逐题门禁保留拒绝结论，没有把数值全部正确作为整句语义正确。该批两次模型派发、费用已知、无新增未知用量，测试数据已清理。

来源的逐科目字段本来正确，旧规则主要强调金额、币种、单位、比较期和“营收不证明订单”，没有明确收入与利润的口径词不能合并。模型把同一回答中相邻的两个科目混成一类，再追加不适用说明，并非财务 Service 错取了归母营收。

## 修复与边界

[ResearchQuestionService](../../../src/main/java/com/stock/system/agent/service/ResearchQuestionService.java) 的 v12 规则明确逐项表述：REVENUE 是收入／营业收入，NOT_APPLICABLE 不适用利润归属口径；归母／股东应占只描述 NET_PROFIT 且 PARENT_SHAREHOLDERS 的利润，同时回答两个科目时不能统称归母。精确数值与原报单位检查继续保留。

这次改动修正模型的科目解释规则，没有声称 Java 已具备任意自然语言的语义证明，也不以字符串替换悄悄修补旧答案。旧失败正文继续保留；离线检查证明原生请求、输入约束和既有程序边界仍正常，语义是否改善必须由同题新的真实输出核对。

## 验证与项目解释

最终 v14 完整批次中，腾讯原年度题三次、茅台及营收边界题均未再混用收入与归母口径，逐条来源核对通过；这是限定题集改善证据，不证明任意自然语言都不会再误用。完整回归、同题独立采样及预算变化只见 [任务第 33 节](../../specs/004-research-agent/tasks.md#33-最终版本完整回归与原题集核对2026-10-21)。

排查顺序是原报字段 → Java 财务快照 → 模型原句：前两层正确而最后一层把科目含义混合，问题在语言组织层。引用身份和十进制数校验能证明来源及字面数值，不能证明“归母”这样的会计口径在句中指向了正确对象。
