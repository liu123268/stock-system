# BUG-001：认证页面热更新后布局样式错位

状态：已解决

发现与修复时间：2026-08-08

历史复盘：该次单列布局后来已由认证双区替代；当前规范见 [视觉设计系统](../../architecture/ui-design-system.md)。

## 1. 问题现象

登录和注册页面模板已经改为新的单列表单结构，但开发服务器热更新后，页面仍表现出旧布局约束，出现“新模板配旧布局”的错位效果。

## 2. 影响范围

影响登录页、注册页及其共享 `AuthLayout`。这是认证页面布局问题，不是全局业务规则或后端认证问题。

## 3. 排查过程

1. 先确认 Vue 模板代码已经更新；
2. 检查浏览器实际计算样式，而不是只观察源码；
3. 对比新组件类名和共享 CSS 选择器；
4. 发现旧布局网格、宽度假设和旧 `.auth-card` 选择器仍在影响新 `.auth-sheet` 结构。

## 4. 根本原因

视觉重构替换了组件模板和类名，但共享布局 CSS 没有完整同步。热更新保留开发状态，使问题看起来像“代码没有生效”，实际是新 DOM 仍继承旧结构约束。

## 5. 解决方案

- `AuthLayout` 明确重置为单列网格；
- 表单容器最大宽度固定为 440px 并居中；
- 共享表单选择器由旧 `.auth-card` 统一为 `.auth-sheet`；
- 检查并移除与新结构冲突的旧宽度和网格假设。

当时用 `grid-template-columns: minmax(0, 1fr)` 显式重置旧网格，`min-width: 0` 允许子项在窄屏收缩；表单使用 `width: min(440px, calc(100vw - 40px))`。这些是历史修复尺寸，不是当前规范。

## 6. 验证

- 运行前端格式化、静态检查、类型检查和生产构建；
- 使用真实 Chrome 验收桌面端和 390px 手机端；
- 当时异常容器约 891px；修复后 1536px 桌面视口为 440px，390px 手机为 350px，两侧各 20px；
- 登录、注册无水平溢出；
- 注册页窄屏可以正常纵向滚动。

## 7. 预防措施

- 重命名组件类名时同时搜索共享 CSS 和测试选择器；
- 布局重构显式重置旧的 `display`、`grid`、宽度和定位约束；
- HMR 只用于快速反馈，不能替代完整刷新、生产构建和真实浏览器验收；
- 布局异常时查看浏览器计算样式和命中的选择器，不只看源文件。

## 8. 可转化的面试问题

- 为什么源码已经修改，浏览器布局仍然可能不正确？
- HMR 能解决什么，不能代替什么？
- 组件类名重构为什么可能破坏共享样式？
- 响应式页面应该如何进行真实浏览器验收？
