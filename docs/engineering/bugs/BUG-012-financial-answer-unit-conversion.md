# BUG-012：财务快照正确，但模型正文金额或百分比单位出错

日期：2026-10-18。影响新旧生成结果需分开核对，不能用修正 Prompt 宣称所有回答已经正确。

## 现象与影响

报告六题 v5／v6 真实比较中，v6 的观点＋财务＋原文组合题返回 SUCCEEDED，引用快照和程序契约检查都通过，但正文将营业收入自行改为亿元并抄错数字：

```text
工具快照：168838102514.79 CNY，单位 YUAN
模型正文：1688.3810251459 亿元
换回元后：168838102514.59，比快照少 0.20 元
```

原始财务目录、Java 同比计算和保存的 FinancialFacts 均正确。错误发生在模型重新表述数字时；不是 MySQL、JSON 数字精度或浏览器浮点换算造成。该失败样本位于 `target/agent-reports-real-20261018-172828-454e0b3d/results.json` 的 report-combined，原文审查记录 `target/report-answer-v6-source-review.json`。v6 的其他五题来源与关键结论可支持，不能把这一题也计为真实质量通过。

v7 真实组合题保留原报元和 **-1.2060%**，但第五题无有效结果导致整批停止。v8 的六题程序契约均通过，组合题金额保持正确，却写成“同比变化为-1.2060”，遗漏百分号；数值字面相同仍造成单位歧义。该样本位于 `target/agent-reports-real-20261018-180654-b031c69a/results.json`，Codex 审查 `target/report-answer-v8-source-review.json`。不能把百分比单位问题当作仅文风问题或已通过。

## 根因

[ResearchQuestionService](../../../src/main/java/com/stock/system/agent/service/ResearchQuestionService.java) 原先确认输出结构、引用 ID、权限及快照版本；[财务检查脚本](../../../scripts/agent-quality/financial-cases.mjs) 核对工具快照中的数字／单位。两者都未验证正文重新写出的金额是否保持原单位和精确数值。“引用存在”不等于“引用支持这句话”，工具已经准确计算也不保证模型照抄。

v6 改善了无关缺口和内部字段外露，但本样本出现换算错误。只观察到版本复测中的失败，不据一次输出断定由哪条新规则导致，也不由费用很小或差额很小降低财务精确性要求。

## 修复与执行链路

v7 明确按工具提供的精确十进制数、原币种和原报单位回答，允许千分位，不让模型自己换成万元／亿元、改币种或四舍五入。[ResearchFinancialAnswerNumbers](../../../src/main/java/com/stock/system/agent/service/ResearchFinancialAnswerNumbers.java) 在新回答解析后、构造成功结果前检查带 FINANCIAL 引用的段落：

- 数值按 BigDecimal 归一后与本段引用材料比对；不经 double，也不将模型换算值写回原快照。
- 常见金额写法进一步核对“数值＋原单位＋已表达的币种”，百分比只采用本次取得的变化值或共同引用原文；数学上正确但 Java 未提供的单位换算同样拒绝。
- v9 进一步区分 Java 百分比数值与其他数字：一个字面若只在财务百分比中出现，正文必须保留 `%`（兼容全角百分号及空白）；仅保留数值、遗漏百分号同样拒绝。若同一数值还确实来自共同引用原文、金额或元数据，不能只因相同数字就断言其一定在表达同比。
- 共同引用的报告、报价／日 K 和成员原文可以保留各自已有数字，年份、日期、页码与股票代码不能被误当成金额。
- 不符合时沿现有 RESEARCH_AGENT_INVALID_RESULT 失败路径结束，不写 agent_message、不展示错误正文；已经发生且已知的模型用量仍结算，不自动付费重试。

## 验证与边界

[数字单元检查](../../../src/test/java/com/stock/system/agent/service/ResearchFinancialAnswerNumbersTest.java) 保留真实错误、正确但未授权的单位换算、只改单位／币种、元与百万元、Java 同比、跨引用来源、共同原文／观点和非财务段落边界；[原生工具检查](../../../src/test/java/com/stock/system/agent/ResearchFinancialQuestionTest.java) 证明即使模型使用真实合法财务引用，错误正文仍被拒绝。最新后端、网页与真实复测结果只见 [任务第 28 节](../../specs/004-research-agent/tasks.md#28-报告六题真实对照与财务正文防错2026-10-18)。

当前保护只作用于**新生成、实际带财务依据引用的段落**，采用现有中文及常见 CNY／HKD／USD 金额写法，不构成任意语言金额解析器；它不能判断数值与科目／期间是否对应、增长下降的语义是否正确，也不能把带引用的成员猜测变为事实。未带财务引用的概念段落和历史已保存正文不作追溯改写。实际答案仍须对照原始快照与原文审查，不能仅凭新增检查宣称模型财务质量全部通过。

## 复习与面试转化

结合本例说明三个验证层次：工具是否准确、结构与引用是否有效、正文是否受到引用支持。需要确定性计算的金额和同比交给 Java；模型负责解释，交付前再核对其使用的数值／单位。发生质量失败时保留失败版本、准确费用和原始依据，再以相同问题集复测；方法入口见 [测试规则](../testing.md#25-研究助手的受控与真实模型检查)，不另维护一份付费授权或数据清理规则。
