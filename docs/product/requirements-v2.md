## 1. 版本定位

V1 是可独立交付的 Java 核心版，范围和完成条件见 [V1 需求](requirements-v1.md)。V2 在 V1 验收之后增加第一阶段单 Agent，保留已确认的 Agent 目标，不将其他 [后续候选](backlog.md) 自动列为 V2 必做项。

本文维护 V2 的产品方向与全局边界；详细流程、设计和任务在进入实施前形成对应阶段规格。当前没有完成详细 Agent 规格，不能仅凭本文件开始完整功能开发。

## 2. 已确认范围与边界

- Agent 提供研究整理、成员观点对比、风险清单和待验证问题；
- 只读工具查询当前用户有权访问的空间自选股、最新可用行情、历史行情和观点时间线；
- 输出带数据来源和行情时间，不能将缺失或过期信息当作当前事实；
- 复用当前用户权限和真实 Java Service，模型不能直接访问数据库、任意接口或另建一套业务与权限；
- 模型服务不可用时，空间、共享自选、行情、观点和超级管理员治理等 V1 核心业务仍须正常运行；
- 本阶段不判断股票是否值得买，不输出自动买卖建议，不自动交易；Multi-Agent 和模型训练不进入这一阶段；
- 短期会话状态与研究上下文隔离纳入主体规划；长期偏好记忆、RAG 和 MCP 在工具闭环稳定后按真实需要评估，不将它们自动列为 V2 首个交付前置。

## 3. 正式讨论采用的规划基线

定位：Java 后端实习／应届能力为底座，V2 主体达到业务 Agent 层，整体为中等偏高难度。难度主要来自数据范围、权限、上下文和回答质量的工程处理；本节确定讨论尺度，不替代具体用户故事和详细验收指标。

主体应形成一条可操作的研究闭环：用户提出问题，模型按需要选择受限只读工具，Java 校验并查询真实研究／行情数据，助手输出带引用、读取范围和数据时间的结果，用户能围绕结果继续追问。整理内容包括共识、分歧、判断变化、现有证据能核对的观察条件，以及证据缺口和待验证问题。

| 主体能力 | 可检查的结果 |
| --- | --- |
| 模型与工具闭环 | 不同问题可触发不同工具组合；信息足够时可直接回答。结构化输出可校验，模型不能生成任意 SQL 或选择任意接口执行 |
| 会话与数据范围 | 用户和研究上下文隔离；分页／截断说明实际覆盖范围；历史会话不能替代当前授权或最新行情。会话记录与运行记录的保存不等于允许修改研究业务数据 |
| 依据与结果展示 | 引用可定位原观点或数据；成员判断、可核对事实和缺失证据分别表达。首个闭环可同步展示，主体逐步提供流式结果和结束／失败反馈 |
| 可靠性与安全 | 从首个模型调用起落实参数校验、权限、总超时、有限调用／重试、并发和输入上限；在工具执行及输出交付边界校验访问，失败不损害 V1 核心流程 |
| 验证与追踪 | 有固定问题集、确定性业务测试和真实模型质量核对；记录模型／提示词版本、调用工具、耗时和用量，支持比较修改前后差异 |

首个场景推荐围绕单只股票、一个研究周期推进；具体问题、页面入口和数据窗口在正式讨论时确定。一次摘要是起步里程碑，主体验收包含完整工具与追问链路。

知识检索与外部工具是第二层学习实践：在真实研究文档需求出现后完成一条 RAG 链路，有工具复用需求时实现或接入一个受控 MCP 服务。它们继续保留为学习目标，不自动扩张主体产品范围，也不要求等全部完成才开始求职。空间周报、通用搜索等仍为候选。

## 4. 实施前待确认

- 第一个用户场景、页面入口和交互方式：明确用户输入什么、得到什么，以及解决哪一步人工工作；
- 数据范围、观点引用和结果展示方式，是否保留生成历史；
- 模型服务与预算、请求和工具调用限制、超时与失败反馈；
- 送入模型的必要字段、会话与运行记录的保存期限，以及流式中断／取消后的行为；
- 第一批工具契约、测试集与结果验收标准。
