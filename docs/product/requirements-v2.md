## 1. 版本定位

V1 是可独立交付的 Java 核心版，范围和完成条件见 [V1 需求](requirements-v1.md)。V2 在 V1 核心业务、权限与数据基础可演示且相应验证可用后，推进已确认的第一阶段单 Agent；用户已要求 V2 开发与学习并行。V1 的非阻塞观察尾项独立保留，当前 CODE-206I 的真实到期刷新仍须验收，不能由普通报价或 V2 进展替代，也不能把 V1 标为全部完成。新发现的权限／数据基础阻塞仍先修复；其他 [后续候选](backlog.md) 不自动进入 V2。

V2 的产品增量以研究 Agent 为主，同时包含支撑它的财务数据读取、个人会话、依据查看、页面反馈和用量保护；这些配套工作属于同一研究闭环。完整 V2 必须包含第 3.3 节的受控文档 RAG 功能；研究、行情与核心财务的先行闭环可提前展示，不能将它称为完整 V2。第 3.2 节的观察条件核对和空间变化简报保留为后续方向；第 3.4 节明确既有 MCP 学习实践的完成边界。头像上传、密码重置、价格提醒、通知等仍按候选清单的各自确认状态与版本待定边界处理，不因准备 V2 自动加入。

本文维护 V2 的产品方向与全局边界；首个场景的 [SPEC-004 需求](../specs/004-research-agent/requirements.md) 中 AG 要求与 P-001～P-007 使用细则均已确认，对应 [设计草案](../specs/004-research-agent/design.md) 为业务方案，[任务计划](../specs/004-research-agent/tasks.md) 区分历史实验、已验证的正式接入与剩余业务。功能开发依据阶段需求落实机制与验收，不将确认方案写成已经运行的功能。

## 2. 已确认范围与边界

- Agent 提供研究整理、成员观点对比、风险清单和待验证问题；
- 只读工具查询当前用户有权访问的空间自选股、最新可用行情、历史行情、观点时间线及有界公司财务事实；
- 输出带数据来源和行情时间，不能将缺失或过期信息当作当前事实；
- 复用当前用户权限和真实 Java Service，模型不能直接访问数据库、任意接口或另建一套业务与权限；
- 模型服务不可用时，空间、共享自选、行情、观点和超级管理员治理等 V1 核心业务仍须正常运行；
- 本阶段不判断股票是否值得买，不输出自动买卖建议，不自动交易；Multi-Agent 和模型训练不进入这一阶段；
- 短期会话状态与研究上下文隔离纳入主体规划；受控文档 RAG 是完整 V2 必做项，按第 3.3 节分阶段实施。长期偏好记忆和主产品的外部金融 MCP 接入按真实需要评估；至少一个 MCP Server 的真实实践须完成，见第 3.4 节，不作为最早可用页面的前置。

## 3. 正式讨论采用的规划基线

以下为调研后的推荐讨论基线，不等同于全部细节已经由用户确认。定位：Java 后端实习／应届能力为底座，V2 主体达到业务 Agent 层，整体为中等偏高难度。难度主要来自数据范围、权限、上下文和回答质量的工程处理；本节提供讨论尺度，不替代具体用户故事和详细验收指标。

主体应形成一条可操作的研究闭环：用户提出问题，模型按需要选择受限只读工具，Java 校验并查询真实研究／行情／财务数据，助手输出带引用、读取范围和数据时间的结果，用户能围绕结果继续追问。首个场景整理共识、分歧、判断变化、证据缺口和待验证问题；独立的观察条件核对按第 3.2 节后续需求推进，不因本节基线自动变为首个交付要求。

| 主体能力 | 可检查的结果 |
| --- | --- |
| 模型与工具闭环 | 不同问题可触发不同工具组合；信息足够时可直接回答。结构化输出可校验，模型不能生成任意 SQL 或选择任意接口执行 |
| 会话与数据范围 | 用户和研究上下文隔离；分页／截断说明实际覆盖范围；历史会话不能替代当前授权或最新行情。会话记录与运行记录的保存不等于允许修改研究业务数据 |
| 受控文档 RAG | 在授权资料范围检索相关段落，再据此回答并定位依据；无匹配或依据不足时如实说明。具体范围见第 3.3 节 |
| 依据与结果展示 | 引用可定位原观点或数据；成员判断、可核对事实和缺失证据分别表达。首个闭环可同步展示，主体逐步提供流式结果和结束／失败反馈 |
| 可靠性与安全 | 从首个模型调用起落实参数校验、权限、总超时、有限调用／重试、并发和输入上限；在工具执行及输出交付边界校验访问，失败不损害 V1 核心流程 |
| 验证与追踪 | 有固定问题集、确定性业务测试和真实模型质量核对；记录模型／提示词版本、调用工具、耗时和用量，支持比较修改前后差异 |

2026-10-08 复核建议：一次摘要是起步里程碑，先行闭环包含受控工具与追问链路，后续做 RAG 和 MCP 实践。2026-10-09 按用户补充，RAG 明确成为第 3.3 节的完整 V2 必做功能；MCP 沿既有实践安排。最早页面无需等待它们同时完成，求职准备仍与项目并行；首个场景先用少量已知样本和一个工具验证，主框架迁移另做实验，不以昂贵金融账号或海量公告采集作为前置。

### 3.1 已确认首个场景：单股研究梳理与追问

2026-10-08 用户确认：在单股研究详情中，针对选定的一个研究周期发起梳理，得到带原观点依据的判断变化、成员差异、证据缺口和待验证问题，并能围绕结果继续追问。读取与回答均受当前用户的空间访问权限约束。

2026-10-08：用户接受结果方向并授权评估优化。首个场景采用“点击研究梳理查看结果，再继续追问”的入口；保留四种信息，将证据缺口与待验证问题合并为待核对事项，并明确要求首次结果默认带最新可用报价。随后接受原文弹窗与个人对话保存、返回继续的推荐方案；进一步确认 P-005 的简易保存与主动清空策略。详细行为与资料不足的处理只维护在 [SPEC-004](../specs/004-research-agent/requirements.md)。数据窗口、保存／清空的实现机制和工具契约仍待落实，不能据此标为已实施。

2026-10-09：用户进一步提出财报属于股票问答，需要明确加入阶段和股票数据边界。按 SPEC-004 的 AG-020、AG-021，将有界财务事实查询纳入先行研究、行情与财务闭环；最早小实验／页面先形成研究＋报价结果，数据源预检尽早进行，财报在先行闭环验收前补齐，不等到 RAG／MCP 才加入。各类数据的来源能力、当前 Java 接入和阶段安排只见 [数据覆盖表](../specs/004-research-agent/design.md#41-股票数据覆盖与接入状态)，不承诺全市场全字段。

### 3.2 后续需求方向与外部数据期望

2026-10-08 用户明确提出以下两个方向后续也需要，保留为后续需求；实施阶段、范围和详细验收仍待难度与数据条件评估，不自动列为首个场景必须同时完成的内容。

| 方向 | 需要解决的用户问题 | 待界定范围 |
| --- | --- | --- |
| 观察条件核对 | 成员提出的观察条件，目前是否有数据或资料可以验证，依据是什么 | 先界定现有行情可核对的条件，再评估公告／财务类条件；缺资料不能当成条件已满足或已被否定 |
| 空间变化简报 | 用户有权访问的一个空间在指定期间有哪些研究、观点和行情变化 | 股票范围、时间窗口、摘要优先级和是否主动刷新；定时周报及推送尚未确认 |

用户同时询问按自然语言提问调用通达信、Wind 等实时信息，并通过 MCP 接入的可行性。当前作为外部数据接入期望继续讨论，尚未选择供应商、确认预算或验证真实连接；技术证据与现成平台复用分析见 [外部数据与平台复用](../architecture/technology-stack.md#33-外部数据mcp-与现成平台复用)。通用搜索仍为候选，不把任何提问都承诺为可回答。

2026-10-09 为学习地图补充推荐起点：观察条件先限已有数据能够核对的明确指标、期间和阈值，由程序计算，结果带依据或无法核对的原因；空间简报先由用户主动生成，限制一个空间、明确时间和股票范围。自动抽取任意观察条件、持续监控、定时生成与推送再按真实需要扩展。以上是后续范围建议，不将尚未确认的细节算作本版交付承诺；MCP 学习先做本项目已有查询，外部金融授权另验。

### 3.3 必做阶段：受控文档 RAG

2026-10-09 用户强调 RAG 是 Agent 学习的重要必做内容。V2 须实际完成与研究助手相连的受控文档检索与有依据回答，不能只保留名词、调用一次框架函数，或以不接业务的独立 Demo 代替完整 V2 交付。技术链路和知识安排只见 [技术规划](../architecture/technology-stack.md#34-可行性验证与知识安排)。

用户能围绕已经纳入资料库的材料提问，助手检索相关文字，再给出带可定位段落依据的回答；材料范围、日期与本次覆盖须明确，无相关段落或段落不能支持结论时说明缺口。股票身份与当前权限继续由 Java 绑定，文档检索不能扩大访问范围；事实数字的同口径查询与计算继续沿已有财务工具，不由相似段落代替完整数字核验。

2026-10-09 用户确认：先由系统提供并维护少量公开公司报告资料，用导入脚本入库；用户在现有股票研究助手中提问和查看依据，不承担资料上传、整理与建库。产品定位是股票研究助手，普通用户上传个人资料不进入本版需求。

初步问题范围是所选报告文字能够支持的业务说明、管理层对变化的解释和已披露风险，例如“报告怎样解释营收变化”“报告提到了哪些经营风险”。这是基于报告陈述的回答，不等于独立证明经营因果或股价原因。第一批推荐从少量 A／港代表公司的可读文字章节开始；具体公司、报告期与官方来源清单经预检落实，界面说明哪些报告已经可用，不能由少量样本承诺全部股票、全部年份和所有报告已入库。

资料维护须包含来源与版本标识、导入状态、重复导入处理、更新和移除，失败资料不能显示为可检索。报告数字和复杂表格继续沿财务事实工具及经核实的口径处理；扫描 OCR、任意 PDF 全文准确解析、全市场自动采集及 Graph RAG 不自动纳入。文档读取、段落定位和中文检索先独立验证，正式接入机制见 [设计第 4.4 节](../specs/004-research-agent/design.md#44-报告资料库与-rag-接入)。

先行研究、行情与核心财务闭环可以先交付，再将 RAG 接入同一个研究助手；完成受控 RAG 的实际检索、回答、引用和质量验证后，才满足本项完整 V2 要求。详细功能尚未定稿，不因加入规划标为已实现，也不以它推迟最早可见成果。

### 3.4 必做学习实践：至少一个 MCP Server

原始学习目标要求自己实现或接入至少一个 MCP Server。V2 的学习验收须包含一个真实可用的受控只读工具及客户端调用证据，不能只写配置或口头解释。站内已有 Java Service 不必全部改成 MCP；这一实践可在独立入口完成，不增加通用工具平台。

优先推荐把本项目已有的一个受限研究查询开放为 MCP 工具，让客户端取得授权范围内的资料，具体身份绑定与传输方式先验证。此推荐不表示已经接入 WorkBuddy，也不承诺通达信／Wind 的账号、付费授权与数据接口已可用；外部金融供应商仍沿第 3.2 节评估。框架、协议和实际验收只维护在技术规划与 AG-CODE-009。
