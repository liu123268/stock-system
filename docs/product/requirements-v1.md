# 同研自选 V1 产品需求

状态：V1 范围已确认；实施进度见项目状态  
产品名称：同研自选（暂定）  
更新时间：2026-09-18

## 1. 文档职责

本文档只规定整个 V1 的产品目标、模块范围、全局规则和最终演示标准。当前阶段的详细流程、权限、异常和验收条件写入对应的阶段规格，不在这里重复。

阶段规格：[SPEC-001 研究空间](../specs/001-workspace/requirements.md)、[SPEC-002 股票研究](../specs/002-stock-research/requirements.md)；当前任务见 [项目状态](../project/status.md)。

## 2. 产品定位

同研自选面向家庭成员和小型投资研究组，把分散在聊天记录和不同软件中的自选股、判断理由、关键观察条件与观点变化整理到同一个研究空间。

首批真实用户约三人，但系统支持多个相互隔离的研究空间，不能把家庭人数或某个固定空间写死在代码中。

产品不执行真实交易，不构成投资建议，不承诺收益。

## 3. V1 功能范围

### 3.1 用户与认证

- 注册、登录、退出和获取当前用户；
- 登录用户可以修改自己的昵称和密码；V1 不包含头像上传和邮箱找回密码；
- 受保护页面由后端验证登录状态；
- 系统级角色包含 `SUPER_ADMIN`，用于最小化的超级管理员治理；
- V1 只设置一名独立的 `SUPER_ADMIN` 治理账号，由开发者通过默认关闭、无公开入口的一次性初始化流程建立账号和唯一管理员关联；公开注册只能创建普通用户，普通用户不能被提升为超级管理员；
- `SUPER_ADMIN` 只使用独立治理后台，不能创建、加入或拥有研究空间，也不能作为 `OWNER/MEMBER` 参与普通空间业务；
- `SUPER_ADMIN` 可以查看用户和空间基础信息、用户所属空间与角色，禁用或恢复用户，治理归档或恢复异常空间，并查看自己的管理操作记录；
- `SUPER_ADMIN` 禁用账号后，该账号的已有登录状态在下一次受保护请求时立即失效；历史数据保留，恢复后可以重新登录；
- `SUPER_ADMIN` 不能默认查看或修改成员观点、冒充用户、代替用户添加股票或执行交易；
- `SUPER_ADMIN` 不提供任意数据库字段编辑、物理批量删除真实账号和空间或绕过普通业务规则的万能权限；
- 禁用用户和治理归档空间属于危险操作，执行前必须二次确认，但 V1 不强制填写操作理由；
- 最小超级管理员治理模块仍属于 V1 必需范围，但在普通用户的邀请、成员和必要归档边界完成后，先进入共享自选、初始观点和多人观点核心闭环；核心用户流程可见后再返回完成最小治理与全量回归，不扩展额外后台能力拖延主线；
- 当前 V1 不包含 Refresh Token、多设备会话管理和第三方登录。

认证实现与边界见 [认证架构](../architecture/authentication.md)。

### 3.2 研究空间

- 空间级角色使用 `OWNER/MEMBER`，不增加空间 `ADMIN`；
- 查看、创建和切换自己加入的空间；
- 通过邀请码邀请和加入成员；
- 查看成员并按已确认权限管理成员；
- 阻止非成员访问和跨空间越权。

详细规则只在 [SPEC-001 研究空间需求](../specs/001-workspace/requirements.md) 维护。

### 3.3 共享自选股与行情

本节保存 V1 的全局产品边界；当前“搜索股票、初始观点、原子添加、共享列表”闭环的具体权限、失败和验收只在 [SPEC-002](../specs/002-stock-research/requirements.md) 维护。

- V1 支持沪、深、北 A 股和港股，保留标准代码的市场后缀 `.SH`、`.SZ`、`.BJ`、`.HK`，例如 `000001.SZ`、`920002.BJ`、`00700.HK`；系统同时保存交易所字段，前端继续展示交易所标识，不能为减少转换工作删除市场身份；
- 按代码或名称搜索标准股票，股票名称、市场和币种由系统提供，不能由用户随意填写；
- 同一空间内同一股票只有一个共享股票身份，但可以形成多段按时间分开的研究周期；同一时刻最多只有一个活动研究周期；
- `OWNER` 和 `MEMBER` 都可以添加共享股票，并把共享状态改为普通关注、重点关注或结束关注；
- 首次添加或重新关注一只股票时，必须同时建立新的研究周期并发表该周期的初始观点，三者必须形成一个完整业务结果；
- 股票已有活动研究周期时，再次搜索不会重复添加或新建初始观点，而是进入现有股票详情发表观点更新；
- 股票此前已经结束关注时，可以重新关注并开启新研究周期，旧周期及其观点保持只读，不被恢复操作覆盖；
- 自动记录添加人、添加时间、关注价格、行情时间和来源；
- 页面展示“最新可用行情”、币种、时间、来源和数据状态，不把延迟或最近收盘数据冒充实时行情；
- A 股价格使用人民币，港股价格使用港币，目标价和止损参考价跟随股票币种；列表和详情页不单独重复显示 `CNY/HKD` 字段，使用标准代码后缀以及 `¥`、`HK$` 价格符号清楚区分；
- 活动研究周期使用普通关注和重点关注状态，结束关注后该周期进入历史并保留，不物理删除；
- 开启或重新开启研究周期前，必须由可信状态来源确认股票尚未退市；正常上市和停牌均允许，交易状态未知或无法核实则阻止开启，不能仅凭仍能取得报价推断未退市。退市股票保留既有历史，但不能开启新的研究周期；
- 行情不可用时明确失败；已有关注记录可以展示最后一次成功行情并标识可能过期，模拟数据必须明确标识；
- V1 使用按需 pull：已加入空间的单只股票可查看分钟／小时／日周月年 K 线并左拖补历史，也可查看当天和历史日期分时；盘中仅刷新当前可见分时。它不承诺逐笔行情、后台全列表刷新或交易所级实时推送，具体额度与失败边界见 [SPEC-002](../specs/002-stock-research/requirements.md)。
- 股票目录与行情接入以零数据订阅费为选型目标；仅在免费方案确实不能满足当前闭环且用户确认具体金额后，才考虑极少量付费，不将付费套餐或试用到期付费作为默认依赖。

### 3.4 多人观点与复盘

- 成员可以围绕共享自选股发表初始观点、观点更新和复盘总结；
- 每条观点属于明确的研究周期；重新关注后产生的新观点不能混入已经结束的旧周期；
- 一名成员可以针对同一股票发表多条带时间的观点，不以新内容覆盖旧内容；
- 作者和发表时间由后端产生；
- 观点包含倾向、判断理由和关注周期，倾向为看多、中性或看空；关键观察条件、目标价与止损参考价选填；
- 观点发表后 5 分钟内允许作者纠正误发：撤销初始观点会取消本期研究并移出正在关注，撤销更新或复盘只隐藏该条正文；所有撤销都保留作者、发表时间、撤销人和撤销时间，超过窗口后只能追加新观点更正；
- `OWNER` 和 `MEMBER` 都只能撤销自己的观点，不能修改或撤销其他成员的观点；
- 撤销不物理删除历史记录；结束关注后旧周期及其观点永久保持只读，重新关注是在新周期发表，不解锁旧周期；
- 可以按成员、倾向和类型查看观点时间线，并查看关注以来的客观价格变化；
- V1 不实现观点回复、点赞、投票、排行榜或 AI 判断观点对错。

### 3.5 页面与交互基线

- V1 包含产品首页、登录注册、空间入口、空间概览、共享自选、股票详情、成员和空间设置等主要入口；
- 空间概览提供站内近期动态，展示新增股票、观点更新和共享状态变化；V1 不发送邮件、短信或浏览器推送；
- 登录后按 0 个、1 个或多个有效空间分别进入引导页、唯一空间或空间选择页；
- 系统一次只展示一个当前空间的业务内容，不建立混合多个空间股票和动态的跨空间大工作台；用户通过明确的空间选择入口切换空间；
- 空间内部提供概览、共享自选、成员和设置四个稳定业务入口：概览负责真实摘要、近期动态和快捷入口，共享自选负责搜索、添加和查看股票，成员页负责成员与邀请，设置页负责空间资料、所有权、退出和归档；
- 股票详情是共享自选和近期动态的下级页面，不作为空间主导航；它承载最新可用行情、当前与历史研究周期、关注信息、观点时间线和发表观点入口；
- 已归档空间在空间选择页的独立区域展示，不与活动空间混排；进入后只读查看历史；
- 个人资料属于空间外的账号入口，负责普通用户修改昵称、密码和退出登录；`SUPER_ADMIN` 使用独立治理入口，登录后进入超级管理员后台，不进入普通空间工作台；
- 空间概览中的“添加股票”等快捷操作只跳转到共享自选中的统一流程，不建立第二套添加逻辑；
- 当前阶段只确认页面职责和完整用户流程，不锁死具体布局、组件、字段密度、颜色或动效；
- 页面实现后通过真实桌面端和移动端使用与测试继续调整交互，但不得在调整 UI 时改变已经确认的权限、数据隔离和历史保留规则；
- 尚未接入的数据使用真实空状态，不以假股票、假行情、假观点或假收益填充正式页面。
- 超级管理员后台使用独立入口，不混入普通空间设置；V1 的空间和观点仅成员可见，不提供公开分享链接。

### 3.6 Agent 增量

- Java 核心业务完成后再增加；
- Agent 复用当前用户权限和真实 Java Service；
- 第一阶段只提供研究整理、观点对比、风险清单和待验证问题；
- 不自动荐股、不自动交易；
- Tool Calling 稳定后再按真实需求评估 Memory、RAG 和 MCP。

## 4. 全局业务规则

- 当前用户、角色、作者、业务时间、行情来源等可信字段由后端产生或验证；
- 账号类型与空间身份分层判断：独立治理账号只能是 `SUPER_ADMIN`，普通账号才可以建立空间成员关系；在某个空间内，当前所有者对外显示为 `OWNER`，其余有效成员显示为 `MEMBER`；
- 所有空间业务请求必须验证当前用户是目标空间的有效成员；
- 成员主动退出或被移除后立即失去空间访问权，但其已经发表的历史观点继续保留给空间成员查看；重新合法加入后，可以查看空间完整历史，包括自己以前的观点；
- 数据库唯一约束和 Service 事务共同保护关键业务一致性；
- 真实页面不展示尚未接入的成员、股票、行情或统计数据；
- 技术采用与学习执行要求见 [工作流](../project/workflow.md)，不作为业务需求重复维护。

## 5. V1 暂不实现

- 真实买卖、资金账户和券商交易连接（不排除 3.3 的服务端只读行情接入）；
- 自动交易、收益保证和 AI 自动荐股；
- 美股、基金、期货和数字货币；
- 头像上传、邮箱找回密码、用户自行物理注销账号；
- 邮件、短信、浏览器推送和空间内容公开分享；
- 面向公众的信息流和复杂量化策略；
- 没有真实边界的微服务拆分；
- 只为堆技术栈引入的 Redis、MQ、Elasticsearch 或 Multi-Agent。

未进入 V1 的学习目标和产品增强统一记录在 [后续版本候选清单](backlog.md)，避免遗忘，但候选不等于承诺实现。

## 6. 整体演示标准

V1 使用两个顺序明确的完成里程碑。第一个里程碑必须能够脱离 Agent 独立运行和验收，第二个里程碑只能在第一个里程碑完成后增加。

### 6.1 Java 核心 V1

Java 核心业务至少形成以下真实闭环：

1. 三名用户能够分别注册和登录；
2. 用户能够创建或加入研究空间；
3. 不同空间的数据互不可见；
4. 成员能够搜索 A 股或港股，首次添加或重新关注时建立新的研究周期和初始观点；
5. 系统自动保存可追溯的行情、添加人和时间；
6. 多名成员能够围绕同一股票形成观点时间线；
7. 同一股票结束关注后可以开启新研究周期，旧周期和旧观点仍可完整查看；
8. 关键权限、事务、唯一约束和失败情况有测试证据；
9. 项目可以复现启动、演示并解释主要技术取舍；
10. 用户可以修改昵称和密码，`SUPER_ADMIN` 可以通过独立入口完成最小系统治理；
11. 价格提醒、头像、邮件、公开分享、观点回复点赞和自动荐股不属于 Java 核心 V1 的完成条件。

### 6.2 V1 最终展示版

- Java 核心 V1 独立验收通过后，再集中学习并增加第一阶段单 Agent；
- Agent 只做研究整理、成员观点对比、风险清单和待验证问题，不判断股票是否值得买，不给出自动买卖建议；
- Agent 复用当前用户权限和真实 Java Service，不能直接访问数据库或另建一套业务与权限；
- 模型服务不可用时，空间、共享自选、行情、观点和超级管理员治理等 Java 核心业务仍须正常运行；
- “Java 核心 V1”是业务完成标准，“Java 核心 V1 + 第一阶段单 Agent”是最终简历展示版本。

各阶段更细的完成条件以对应 `docs/specs/` 规格为准。
