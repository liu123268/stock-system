# 基点后续版本候选清单

更新时间：2026-09-29

## 1. 文档职责

本文档记录已经讨论过但不进入当前 V1 核心范围的产品增强和学习目标，供核心闭环完成后或 V2 规划开始时重新评估。进入本清单不代表承诺实现，也不能写成项目已经使用的技术。

重新评估每项候选时，需要说明真实场景、候选方案、引入成本、失败方式、测试方法和退出方案；确认进入某个版本后，再迁移到对应版本需求或阶段规格。

本文主要承接后续产品范围；已经确认但暂不实施的需求保留其确认状态，不因放入候选清单而被取消。Java 基础、SQL 优化、测试、算法与面试准备按 [实习准备路线](../project/roadmap.md#实习准备与阶段关系) 推进，不因产品增强推迟到 V2 而一并推迟学习。

## 2. 用户与账号

### 2.1 头像上传与阿里云 OSS

- 目标：学习文件上传、对象存储、访问地址、文件类型与大小校验、旧头像清理和默认头像处理；
- 当前决定：V1 资料与安全入口允许修改昵称和密码，不实现头像上传；
- V2 评估重点：是否存在真实头像需求，阿里云 OSS 成本和凭据管理，上传安全、私有或公开读策略，以及本地开发替代方案。

### 2.2 忘记密码后的密码重置

- 已确认的后续需求：用户忘记密码时必须能够通过受控流程重置为新密码；系统不能尝试找回或展示原密码；
- 当前决定：V1 只支持登录后修改密码，不实现忘记密码重置；该能力保留到后续版本，邮箱验证是当前候选方向，但不在本清单中提前锁死具体实现；
- 进入版本规格时需要明确：身份核验渠道、一次性重置凭据的有效期与使用次数、防枚举、旧登录状态处理、外部服务成本、失败重试和测试清理边界。

### 2.3 用户自行注销

- 当前决定：V1 不允许用户物理删除账号，由平台禁用或恢复；
- V2 评估重点：注销后的观点作者保留、空间所有权转让、个人信息匿名化、恢复期和关联数据处理。

## 3. 提醒与分享

### 3.1 价格提醒

- 目标：达到成员设置的价格条件时产生提醒，并形成定时任务、幂等和失败重试的真实学习场景；
- 当前决定：不进入 V1 最终演示边界，作为 V2 候选；Java 核心业务和第一阶段单 Agent 都不依赖价格提醒；
- 评估重点：行情刷新频率、提醒条件、重复触发、交易日、停牌、通知渠道和供应商限制。

### 3.2 外部通知

- 当前决定：V1 只在空间概览展示站内近期动态，不发送邮件、短信或浏览器推送；
- V2 评估重点：真实通知需求、用户订阅偏好、发送频率、失败重试、成本和隐私。

### 3.3 公开分享

- 当前决定：V1 空间和观点只对有效成员可见，不生成公开分享链接；
- V2 评估重点：脱敏范围、链接有效期、撤销、搜索引擎收录和行情展示授权。

## 4. 协作增强

- 观点回复、点赞、投票和成员提及；
- 更细的空间 `ADMIN` 或可配置权限；
- 当前决定：V1 保持 `OWNER/MEMBER` 和时间线式观点，不把产品扩展成公开社区；
- V2 评估重点：是否出现真实协作需求，以及内容治理、通知和权限成本。

## 5. 市场和数据范围

- 美股、基金、期货和数字货币；
- 更复杂的财务指标、资金流向、新闻情绪和盘口数据；
- 当前决定：V1 市场范围仍只覆盖 A 股和港股；已进入当前规格的能力包括标准搜索、最新可用行情、九种周期 K 线、左拖补载和当天／历史日期分时，精确边界见 [SPEC-002](../specs/002-stock-research/requirements.md)；
- V2 评估重点：数据来源合法性、币种和交易日历、费用、频率限制与展示条款。

## 6. 可配置研究模板与完整元数据能力

- 当前决定：V1 只采用审计、数据来源和业务追溯所需的轻量元数据，不建设 EAV、动态表单或通用流程平台；
- V2 触发条件：多个空间确实需要不同研究模板或自定义字段；字段变化频繁到每次修改代码和数据库已经形成明显成本；出现多个需要用户配置的稳定工作流；
- V2 评估重点：强类型扩展表、JSON 扩展字段和完整元数据模型三种方案的查询能力、约束能力、迁移成本、前端渲染复杂度与测试成本；
- 不满足上述触发条件时继续使用明确业务字段，不能只为技术展示引入元数据平台。

## 7. Agent 自动荐股与买卖建议

- 当前决定：Java 核心业务完成后增加的第一阶段 Agent 只做研究整理、观点对比、风险清单和待验证问题，不直接判断股票是否值得买，不输出自动买卖建议；
- V2 评估重点：是否存在真实使用需求，行情与财务数据是否足够可靠，如何建立可重复的推荐质量评估，如何表达不确定性，以及投资建议相关的风险与合规边界；
- 未满足上述条件时，继续由 Agent 提供决策所需证据和风险，由用户本人作出最终判断。

## 8. 复查时点

至少在以下时点复查本清单：

1. Java 核心业务闭环完成后；
2. 准备 V1 最终演示前，确认候选功能没有被误写成 V1 已实现范围；
3. V2 需求规划开始时；
4. 出现真实用户需求或明确学习验证目标时。
