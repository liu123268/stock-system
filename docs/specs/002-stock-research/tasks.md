### CODE-206E Redis 共享行情缓存：实施目标与验收条件

目标：Redis 只服务已经接入的真实行情读取，解决进程内缓存不能跨 Java 实例共享、进程重启即消失、热点请求可能重复访问 sidecar 和 Redis 故障时缺少明确降级边界的问题；MySQL 继续保存股票身份、研究周期和观点事实。

实施顺序：

1. 先梳理报价、最近 K 线、历史 K 线、当天／历史分时和交易日历的现有调用与缓存位置，定义统一缓存接口；
2. 设计包含股票代码、周期、数量、日期边界等完整条件的 Key，并为短时行情、已收盘历史和交易日历分别配置 TTL；缓存值保留数据来源与供应商时间，不保存 Token 或其他凭据；
3. 采用 cache-aside：命中 Redis 直接返回，未命中时对同一个 Key 合并并发请求，取得 Longbridge 数据后再写缓存；权限和 `workspace_stock` 校验必须发生在返回行情之前，不能因缓存命中绕过业务访问边界；
4. 对无效参数和不存在的本地股票先在应用层拦截，热点 Key 使用请求合并／受控锁防击穿，TTL 使用抖动避免同批 Key 同时失效；不把任意上游错误长期负缓存；
5. Redis 不可用时明确降级到现有进程内短缓存和受限 Longbridge pull，继续遵守每秒 10 次、并发 5 次以及 K 线接口限制；不得把过期值伪装为最新行情；
6. 增加命中、未命中、回源、合并请求和降级的可观察证据，并用单元／集成测试证明相同 Key 不重复回源、不同 Key 不串数据、TTL 到期会更新、并发击穿受控、Redis 故障可降级；涉及数据库的测试仍只连接 `stock_system_test` 并回滚；
7. 完成后做后端回归、前端回归和真实只读页面验收，确认浏览器响应、日志、Redis 值和构建产物均不含供应商凭据，再把 CODE-206E 标为完成。

本任务暂不实现 WebSocket、SSE、行情永久落库、研究业务缓存或多实例 sidecar；Redis 能减少重复上游访问，但不能解除 Longbridge 单账号单行情连接和供应商配额限制。

### CODE-206E Redis 共享行情缓存实施中证据（2026-09-11）

- Spring Boot 已加入 Spring Data Redis（Lettuce），`CachingLongbridgeMarketGateway` 作为四类 Longbridge Gateway 接口的首选装饰层；Redis 命中直接反序列化，未命中才进入原 `LongbridgeJsonRpcClient` 的进程内缓存／sidecar，因此 Redis 故障不会切换 Mock 或绕过原上游限流。
- Key 使用 `stock-system:market:v1` 版本前缀，并完整区分报价代码集合、K 线代码／周期／数量／latest 或日期边界、当天分时以及 CN/HK 交易日。报价／当天分时 5 秒、最近 K 线 1 分钟、已确定不含当前周期的历史批次 12 小时、可能包含未收盘周期的历史请求 1 分钟、交易日 24 小时，写入附加 10% 抖动；空集合不做长时间负缓存。
- 同 JVM 使用 `CompletableFuture` 合并相同 Key；实例间使用带租约的 Redis `SET NX` 所有者锁，释放锁用 Lua 比对 owner 后删除。锁竞争者短时轮询共享结果，超时才受控降级；连接／命令异常触发 30 秒 Redis 冷却，期间直接回到原进程内缓存与 Longbridge。
- 原始报价、K 线和分时点新增真实回源 `retrievedAt`，Redis 命中后继续返回首次回源时间，不把缓存读取时间冒充上游获取时间。缓存 JSON 保留供应商行情时间与来源所需原始值，不保存 OAuth Token、App Secret 或任意供应商凭据。
- 新增单元／装配测试覆盖同 Key 命中、不同参数隔离、完整时间边界、五个固定只读 RPC 方法对应的缓存路径、TTL 更新、同进程合并、跨实例锁等待、Redis 失败冷却、锁所有权、配置绑定以及 Redis 开关两种 Spring 装配。后端全量 98 项中 92 项执行通过、6 项显式真实探测跳过，实际连接 `stock_system_test`；并发测试用户和 `TEST_DIRECTORY` 股票残留均为 0。
- Ubuntu WSL2 已安装 Redis Server 7.0.15。独立真实集成测试实际验证 `PING`、字符串写读、TTL 过期、锁释放和两个缓存网关共享同一报价；Redis 值保留 `retrievedAt` 且不含凭据字段，随机测试 Key 清理后无残留。本轮临时 Redis 已关闭，Redis 进程为 0，6379 已释放。
- 已完成：前端单元测试、类型检查、lint 与生产构建；独立真实 Redis 测试也已完成，但其上游使用替身，不能代替真实 Longbridge 页面验收。
- 未完成：真实 Longbridge 页面命中／未命中／Redis 故障降级证据，以及对压缩后的后端 JAR 和前端产物执行可复现的凭据检查。因此 CODE-206E 仍保持进行中。

### CODE-206E 本地 Redis 连接与自动启动证据（2026-09-14）

- Windows 端已有若依 Redis 使用 `127.0.0.1:6379`，未停止、覆盖或改用它；stock-system 的 Spring Boot 开发配置和真实 Redis 集成测试改为连接 Ubuntu WSL2 的 `127.0.0.1:6380`。这是本机开发环境的端口隔离，不把 WSL 当作生产部署规则。
- WSL 中实测 Redis Server `7.0.15`：`redis-cli -p 6380 ping` 返回 `PONG`，Windows `127.0.0.1:6380` 端口可达；`INFO memory` 约 `941KB`，`DBSIZE=0`，`maxmemory=0` 表示没有设置内存上限。独立真实 Redis 集成测试通过，覆盖连通、读写、TTL 到期、锁释放和两个缓存网关共享结果。
- 本机缓存实例以 `--dir /tmp --save "" --appendonly no` 运行：不生成 RDB 快照，也不写 AOF；因为行情缓存可以从 Longbridge 重新获取，Redis 在此处是加速层和共享层，不是 MySQL 事实数据或备份。生产环境是否持久化必须另行按可靠性要求设计，不能照搬本机设置。
- Windows 当前用户登录启动项直接调用 `wsl.exe` 启动 `6380`，命令带 `PING` 检查，重复执行不会创建第二个 Redis；项目中没有遗留启动脚本。该设置属于“登录后自动启动”，不是每次请求启动，也不是管理员级系统服务；撤销命令见 [开发环境 Redis 章节](../../engineering/development.md#10-redis-本地学习环境)。
- 对 K 线缓存的学习结论已确认：缓存保存的是完整查询结果快照，不是只保存最后一根 K 线；相同股票、周期、数量和边界在 TTL 内可直接复用。历史 `before` 请求现按市场时区的当前周期起点判断：确定不含当前周期才使用 12 小时，否则降为 1 分钟；Redis 仍不能自动解决所有不同 Key 的重复请求。
- 本轮同步更新开发环境、缓存设计和项目状态文档；文档检查 `scripts/check-docs.py` 通过。随后又明确本机数据库用户名属于非敏感普通配置，数据库密码和 JWT 密钥虽移出 Git，环境变量本身并不加密，生产仍需密钥管理服务。CODE-206E 仍待真实 Longbridge 页面命中／未命中／Redis 故障降级及凭据检查，保持未完成。
