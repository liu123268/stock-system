# SPEC-003：预览风格迁移需求

日期：2026-09-30。原 V2 及内容补齐副本保留；正式前端按分块计划实施，实际验收只见 [tasks](tasks.md)。

## 1. 范围与依据

- UI-001：沿用现有 Vue 前端，将首页、认证、个人资料、空间与治理后台迁移至用户预览的视觉和布局方向。视觉正文见 [视觉规范](../../architecture/ui-design-system.md)，页面对应及差异处理见 [迁移设计](design.md)。不再要求用户重新描述审美或自行列出页面差异。
- UI-002：预览决定视觉方向；当前业务规格与实际代码用于核对必须承接的功能、数据、权限及状态。预览是示意，不是 API、权限或数据规则的替代品；规格与实现不一致时记录差距，不自行删需求。
- UI-003：由 AI 处理普通排版、换行、组件复用和不改变含义的文案调整。只有实际涉及增删功能、权限或改变主要操作含义的取舍，才提供具体前后行为及推荐方案供用户判断；不把全部细节交还用户。
- UI-004：按 [任务清单](tasks.md) 逐块迁移、验证并清理，不一次性覆盖全站。计划完成不等于已获本轮实施指令。

业务正文继续由 [空间需求](../001-workspace/requirements.md) 与 [股票研究需求](../002-stock-research/requirements.md) 维护。本阶段不新增数据库、接口、供应商接入或业务规则，不切换前端框架，不把换色器、角色模拟器和占位外链做成正式功能。

## 2. 功能与内容承接

- UI-005：保留现有页面和有效入口，包括预览未画全的创建空间、改名、个人资料、密码修改、真实近期动态、研究详情行情、筛选及分批读取。业务状态必须来自真实响应，明确标识的已有 mock 行情继续保留其模拟标识。
- UI-006：文案可以精简，但不能混淆开始关注价与最新报价、最近个人观点与空间共识、价格变化与投资收益、归档与删除、前端隐藏与后端授权。字段名称、必填规则及操作后果沿用业务正文。
- UI-007：每块同时承接加载、空数据、失败重试、提交中、成功、无权限和归档只读等适用状态；真实长名称、长观点、多人多条数据需要可读，不能只适配预览的固定示例。
- UI-008：复用现有 ECharts、请求及生命周期，保留周期切换、历史加载、日期选择、分时刷新、报价来源和时间。首页若使用示意图，局部标明示意，不当成用户资产、真实行情或平台运营指标。
- UI-009：桌面与窄屏均可完成主要任务，支持键盘和减少动态偏好；视觉验收以浏览器实际页面为证据，编译通过不等于页面观感通过。细则沿用视觉规范。
- UI-011：登录与注册切换时，说明区、表单标题、首项输入、显示密码、提交按钮、切换链接与页脚保持相同纵向位置；不能因字段数量或说明文案换行而跳动。真实校验与请求错误允许自然增高，不能裁剪反馈来维持高度。
- UI-010：补齐功能必须保留用户选择的 V2 样式、动画、效果、首页排版和空间选择页，不得用现有系统页面套主题替换预览。先复制为 `stock-workspace-demo-v2-content-aligned.html`，只在副本增补缺少的字段、统计、按钮、表单及适用状态，原版与设计备份保留。现有系统用于核对业务内容，不决定新预览的页面结构。对股票、周期、观点等嵌套关系保留明确的源码对应，不为预览补造接口字段或建立另一套生产业务实现。用户已确认品牌名称改为“基点”，名称正文见 [产品原则](../../product/product-principles.md)。

## 3. 完成边界

- 每块通过其行为验收和视觉核对后才勾选；构建、截图、测试等按实际执行记录，不沿用旧阶段通过数。
- 已迁移页面原位替换，不留下无用途的新旧双实现。仍被未迁移页面依赖的组件暂留，最后一个使用者迁移后才删除。
- 完整迁移包含旧预览路由、轨道组件、旧样式与素材引用的退出核对，以及当前视觉文档和代码的一致性；历史教学与 Bug 资料保留其历史身份。
- 只把已经通过对应验收的迁移块标为完成，不将 UI 迁移解释为目录覆盖、部署或 Java 核心 V1 已验收。
