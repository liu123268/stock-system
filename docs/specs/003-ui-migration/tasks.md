## 2. 各块共用验收方法

2026-09-30 复核补充：各块还须按 [design 的开工前复核](design.md#2026-09-30-开工前复核容易遗漏的行为约束) 选择对应风险场景。UI-01 开始先取得旧页面／参考的浏览器对照，建立公共样式后逐页巡查六个空间子页；这一步不把六页全部重做。共享图表单实例、异步退出、写入成功但刷新失败、路由复用、跨账号清理和测试定位迁移不得等到 UI-10 才检查。

1. **可审阅的变化**：解释原页面职责、这次模板／样式调整及保留的数据流；对照恢复后的 V2 设计预览，明确真实数据适配造成的差异，附实际视口或截图证据。源码生成实验的浏览器证据不适用于恢复后的 V2，正式源码每块仍需自己的前后验收。
2. **静态与构建**：在 `frontend` 运行类型检查、只读 lint、构建，确认模板／类型／导入及资源仍可交付。运行方式沿用 [测试规则](../../engineering/testing.md)，不执行带自动修复的验收命令去改任务外文件。
3. **行为检查**：运行受影响的现有单元测试；仅为实际变动的行为补充有价值的测试，不为每个颜色或间距新增镜像断言。浏览器使用真实 test 后端与隔离库，按表中场景验证。目录／行情入口用 directory smoke，研究与空间用 auth smoke，治理用 admin smoke；现有脚本若无对应覆盖则补充定向检查，不假设脚本名代表全覆盖。
4. **视口与状态**：建议以 1440px 桌面、960px 附近布局切换和 390px 手机为代表，再检查 320px 最窄边界及长内容；这些是本次验收采样，不新增全项目设备限制。关注可读性、焦点、对比度、溢出、图表尺寸、减少动态和字体未加载时可用性。正常／加载／空／错误／只读等状态按该块适用项覆盖。
5. **同步清理**：每块核对失效 DOM、CSS、导入、定时器和素材；暂留依赖注明使用者，最终统一退出。共用组件调整后复核其他使用者。
6. **完成证据**：记录本块实际命令结果、浏览器范围、保留差异、尚未验证边界和清理结果。数据与服务清理只引用测试规则，不另建第二套规则。未通过不勾选。

只改前端展示且接口无变化时，不机械重跑全后端单元测试；浏览器仍验证真实业务链路。发现必须修改业务／接口时先回到规格核对范围。UI-10 执行完整前端检查和跨模块浏览器回归，实际部署或真实供应商探测仍属于其他阶段。
