### 已识别的差异处理

1. **股票卡片的“查看行情图”**：第一轮保留现有列表内展开及收起，用预览的按钮和面板语言呈现；预览点击后跳页不作为删除现有操作的依据。搜索结果仍进入独立行情页，股票名称进入研究详情，“查看全部观点”仍带时间线锚点。
2. **研究表单**：保留默认收起、明确发表或开启新一期时展开、待确认草稿自动展开，不照搬预览常驻表单。初始与追加表单可以共享控件样式，不强行合并不同提交职责。
3. **研究详情行情**：预览未呈现而项目已有，放在股票身份之后、周期操作之前；从时间线锚点进入仍先收起图表，避免异步高度破坏定位。行情失败不遮住成功加载的研究记录。
4. **字段文字**：预览“观察备注”适配为既有“关键观察条件（选填）”，“判断期限”按既有业务用语“关注周期”统一；不改变字段含义、可空性、长度和数值校验。
5. **缺失接口字段**：预览的最近进入时间、行情页“较昨收”摘要、发起人等只在对应响应确实提供且语义匹配时展示。当前单股行情详情 VO 没有昨收或发起人字段，不从图表的不同日期数据猜值，不为装饰新增接口；保留最新报价、时间、来源及真实关注状态。
6. **统计与演示**：首页示意图保留可辨认的演示说明；业务页不统一贴“示意数据”，按响应保留真正的模拟标识。预览的“腾讯行情”、固定价格和固定人名不硬编码到业务页。空间列表无归档时间字段时不伪造日期。
7. **品牌文字**：2026-09-30 用户确认名称为“基点”，新审阅副本使用该名称，原设计文件仍保留“见微”占位，正式页面随迁移更新。“房间”等修辞可在说明中使用，功能名称和反馈保持“空间”一致。
8. **角色**：不移植角色切换工具。普通用户与超级管理员沿用真实路由和后端授权；个人资料依然支持两种账号访问。

## 3. 样式与代码迁移方式

### 字段归属与嵌套关系

以下路径均相对 `frontend/src`，表中只说明绑定归属，不复制完整 DTO 定义。迁移时对照这些既有层次修改展示，不能为排版把多个对象揉成一份新业务数据。

| 页面内容 | 原始字段与关系 | 现有使用者及边界 |
| --- | --- | --- |
| 空间身份、成员数、状态 | `workspace.currentWorkspace.role/memberCount/status` | `WorkspaceOverviewView`、`WorkspaceLayout`；不是研究接口字段 |
| 正在关注数、近期动态 | `WorkspaceOverviewResponseVO.activeStockCount/recentActivities[]` | `WorkspaceOverviewView` 直接请求 `getWorkspaceOverview`；计数不取最近动态数量，动态不再标“规划中” |
| 邀请码与历史 | `currentInvitation` 含完整代码；`invitationHistory[]` 无完整代码 | 仅活动空间 OWNER 展示管理区；生成、停用与生成历史保持各自状态 |
| 自选卡片 | `WorkspaceStockListResponseVO` 的关注价快照、`latestOpinion*`、`opinionCount/participantCount` | `WorkspaceStocksView`；最近个人观点不变成空间共识；卡片的查看行情仍原位展开 |
| 最新行情 | `WorkspaceStockMarketDetailResponseVO.price/quoteTime/source/simulated/trackingState` | 独立行情页和研究页；与周期开始快照分开，缺报价不丢股票身份 |
| 当前周期与完整时间线 | `researchDetail.currentCycle`；独立 timeline 响应 `cycles[] → opinions[]`、`nextCursor` | `WorkspaceStockResearchView`；摘要不承载完整历史，跨批合并同一期；撤销保留占位而隐藏正文 |
| 提交对象 | 追加观点含 `researchCycleId`；开始新周期含 `code`；撤销使用 `opinionId` | `StockInitialOpinionForm`、研究页及 `stock.ts`；不能因表单外观相近而合并为同一提交职责 |
| 行情图 | K 线 `candlestickSeries.candlesticks[]`；分时 `intradaySeries.points[]/tradingSessions[]` | 三处复用 `StockMarketPanel`，继续用现有 ECharts；同一时刻只挂载一个活动面板 |
| 治理详情 | 用户 `memberships[]`；空间 `members[]`；列表分页 `items/total/totalPages` | 三个 admin 页与 `AdminLayout`，只展示治理字段，不混入研究正文 |

正式迁移使用原位 template/style 改动和现有业务逻辑，不把生成 HTML、内存 adapter 或压缩后的 Vue 包复制到 `frontend/src`。预览不是第二个生产前端。清理判断仍按下文“使用者及最后迁移批次”执行，不因为某字段在默认状态未显示就删除它。

- 原有 `api → Store／页面逻辑 → Vue 模板` 数据链继续使用，优先改 template 和 style；脚本改动限于必要的展示派生状态、焦点及布局生命周期，不能整段替换而丢失竞态保护、重试、草稿或请求清理。
- 第一块把新视觉应用到空间布局与空间选择，并建立最小公共控件规则。保留已有语义变量名；实施时在已迁移根容器下覆盖变量与限定公共选择器，避免全局 `button/h2/input` 直接污染未迁移页面。未迁移子页继续工作，不声称已完成视觉验收。
- 不建立每页一份 `V2` 副本或永久双主题开关。旧根变量在迁移期间只服务尚未完成的页面；最后一块统一根变量、移除过渡覆盖，保留正常的页面作用域边界。
- 共用按钮、表单状态、标签和提示样式；仅在模板或交互确实重复时抽 Vue 组件，不为所有 HTML 元素加一层组件。布局仍由业务页面负责。
- 认证页继续复用现有 Element Plus 表单能力，通过有限作用域的主题与样式适配，避免为换外观重写校验和键盘行为。
- 管理端逐项把写死颜色与行内成功／失败样式归入统一语义规则，仍保留独立 AdminLayout；其样式须在后台容器内生效。
- ECharts 的颜色在 TS option 中，需要单独对接主题；只有改 CSS 不能完成图表迁移。图表挂载、resize、dispose 和计时器行为随页面一起验证。
- 若共用组件的修改影响尚未迁移页面，当块增加这些使用者的兼容性检查；不能以“以后会迁移”为理由接受功能回退。

## 4. 每块怎样交付与恢复

### UI-01 实施落点

- `main.css` 在 `.research-theme` 下覆盖已有语义变量并提供品牌、文本操作、只读标签和跳转内容链接；网格与静态噪点不接收点击。根变量继续服务未迁移的公开、认证和治理页面。新展示字体使用本机回退，不增加外部字体请求。
- 空间选择采用预览的上方说明、左侧行式列表／空状态创建、右侧邀请码区；归档行可进入。数据仍来自 `workspace.ts` 的真实 VO，没有新增装饰字段或预览 adapter。
- 外壳提供四项导航、按路由名称派生的当前位置、底部个人资料／退出和手机导航。行情、研究详情归属“共享自选”。主动切换携带 `reason=switch` 停留选择页；无 reason 的登录入口仍按唯一活动空间自动进入。
- `RouterView` 只以空间 ID 为 key；更换空间时清理旧缓存并卸载旧子页，使原来只在 mounted 加载的成员、设置等页重新读取。股票参数仍由现有页面监听处理，不增加 KeepAlive、并行 RouterView 或重复行情面板。
- 空间列表、邀请和成员读取增加请求版本；清理使未完成请求失效，创建／加入另核对会话版本，选择页卸载后不再导航。创建／加入的 POST 已成功时，列表刷新失败仍使用保存响应进入目标空间，不让用户重复写入；初始加载失败的重试仍只 GET。
- HTTP 失败携带“是否属于旧会话”的布尔值，由请求的认证头与当前会话比较得出，不将 Token 写入错误对象；空间错误处理忽略已退出／旧会话的响应，保留当前会话真实 401 的清理。实际退出竞态复盘见 [BUG-006](../../engineering/bugs/BUG-006-stale-session-response.md)。

这里只记录 UI-01 必需的展示派生、路由生命周期和异步边界修复；其余子页的排版及完整图表生命周期验收仍归各自迁移块。

### UI-02 实施落点

- 共享自选原位改为参考的衬线标题、统计条、搜索面板及细线股票卡片；保留真实 VO、原路由、搜索候选和列表摘要，不复制示例价格、作者或 SVG 图表。关注价格补充快照时间和币种，最近观点保留个人作者与类型，本期计数直接使用接口统计，包含撤回记录占位。
- `q` 参数监听负责同组件复用、前进／后退及搜索恢复；提交仅更新参数或重新读取相同关键词，不并行发两次搜索。离页清理搜索，旧搜索错误不得改变新页导航，Store 继续保护迟到结果。
- 正在关注与历史研究分别呈现失败和重试；历史读取失败不伪装为没有历史，列表失败时数量显示暂不可用。关注级别写入成功后的刷新失败仍明确提示已保存，重试只重新 GET；离页使旧写入回调的后续刷新失效。
- 股票切换先卸载再挂载，维持一个活动行情面板；分时请求在卸载、切模式、换参数后不得重新调度。复现与修复见 [BUG-007](../../engineering/bugs/BUG-007-market-panel-delayed-refresh.md)。图表排版、ECharts 主题及初始观点表单视觉仍归 UI-03，研究详情仍归 UI-04。

### UI-03 实施落点

- 独立行情页按参考重排股票身份、报价及来源／时间，再呈现真实图表；保持 `workspaceId + code` 的只读入口、搜索 query 返回、活动周期研究入口，以及归档、退市、未知状态和无报价的准入限制。初始观点仍在用户点击后展开，取消返回触发按钮焦点；提交期间禁用输入和取消，校验与可选金额的 `null` 语义不变。
- 共用 `StockMarketPanel` 保持单实例与条件挂载，工具栏响应式换行；K 线／分时、九种周期、日期、历史分页和刷新生命周期沿用原逻辑。两个 ECharts 组件从宿主读取语义变量，统一画布、坐标和挂到 body 的提示框；红涨绿跌、价格／均价、成交量和百分比轴保留。窄图表调整边距，同时提供默认 media 配置，使窗口恢复宽屏时恢复坐标边距。
- 行情页加载和提交回调核对页面版本与卸载状态；Store 提交版本在清理行情页时失效，迟到 POST 不触发旧目标列表刷新或导航。失效只控制浏览器后续行为，不能撤销服务器已经成功的提交。
- 初始观点 POST 成功后列表 GET 失败，进入研究详情又读取失败时，保留已保存的反馈；重试只读取详情、时间线及列表，不重复 POST。研究详情本块只修改进入页面的结果反馈，排版仍留 UI-04。复现与教学见 [BUG-008](../../engineering/bugs/BUG-008-saved-result-lost-on-navigation.md)，真实验收见 [UI-03 任务证据](tasks.md#ui-03-正式迁移2026-09-30)。

### UI-04 实施落点

- 研究详情原位承接当前报价、当前周期、观点／复盘表单和按周期分段的时间线；桌面作者／正文／时间三列，窄屏单列。真实昵称、用户 ID、类型、倾向、周期、价格参考、观察条件与撤销占位全部来自原 VO。没有新增接口、数据库或示例数据适配层。
- 报价独立读取，沿用代码／币种／模拟状态／报价时间与正价格检查；无报价、早于开始价或无活动周期不显示价差。图表仍是一个带稳定 key 的条件挂载面板，折叠会卸载；归档只读仍可读报价、查看图表、筛选历史。
- 时间线继续由服务端筛选并按 cursor 每批 20 条读取；以周期 ID 合并、观点 ID 去重。首批失败显示错误，更早一批失败保留已读内容；加载函数明确返回成功与否，保存后的读取失败不会被当作写入失败，重试仅 GET。
- 同组件参数切换清理草稿、确认区、筛选和本地提示。页面版本保护渲染、导航及每个 await 后的提示；Store 独立的研究写入版本在清理时失效，旧 POST 不再发起旧目标刷新，也不覆盖新操作状态。已在服务器成功的写入仍保留，后续查看原股票可读到。
- 草稿和结束确认各自绑定开启操作时的研究周期 ID。其他成员结束并重开后，旧目标交给原后端拒绝；重新加载后不静默把草稿迁到新周期，用户先确认当前周期，再手动发表。撤销仍保留作者／发表和撤销时间，隐藏正文与价格，前端时钟收起过期入口，最终资格仍由后端校验。
- 研究页的 `#research-timeline` 由页面在数据和上方报价布局完成后定位；路由仅对该入口返回 false，保留其他页面的历史位置／顶部策略。目标通过 scroll-margin 避开顶栏，减少动态偏好时直接定位。

数据流教学见 [前端工程](../../engineering/frontend.md#ui-04-中的业务目标与异步回调)，旧写入回调风险见 [BUG-009](../../engineering/bugs/BUG-009-research-target-lifetime.md)，验收见 [UI-04 任务证据](tasks.md#ui-04-正式迁移2026-09-30)。

开工时先用浏览器检查对应旧页面和参考画面，记录目标视口及已有异常，作为当块前后对照；此前只有源码分析，不能宣称像素一致或全部交互无误。关注首次直接访问及跨页访问后的样式表现，避免懒加载样式加载顺序造成偶发差异。短时间的新旧视觉并存允许，业务回退不作为过渡期可接受结果。

每块开始核对 Git 状态及参考版本，记录实际修改文件；完成后先通过 [tasks](tasks.md) 对应行为和视觉检查，再删除已无引用的旧选择器、导入和素材。仍有使用者的依赖暂留，记录其最后清理批次。

采用“源码与可见行为、相关测试、浏览器视口证据、残留引用”共同核对；零引用搜索不单独证明代码无用，也不能把动态生成的类误删。旧 CSS 的删除基于旧 DOM 已替换及其使用者确认。

分块变更以可独立审阅的 diff 交付，提供中文提交信息但不自动提交。发生回退只恢复当前块已确认由本次产生的改动，保护用户原有工作；已有提交时按明确授权处理，不使用全目录 reset／clean。每块结束保留可运行状态。

测试与数据／进程清理只按 [测试规则](../../engineering/testing.md) 执行。独立预览只启动临时浏览器、不启动业务服务、不写数据库；正式实施阶段默认用隔离 mock 行情验证 UI，不把接真实供应商作为每块前置，也不据此宣称真实供应商验收完成。
