# SPEC-001：研究空间需求规格说明书

状态：已确认，可开发  
所属产品：同研自选 V1  
更新时间：2026-09-03

## 1. 文档职责

本文档是研究空间阶段唯一的详细业务需求来源，保存范围、流程、规则、权限、失败情况和验收标准。数据库、接口和代码方案见 [技术设计](design.md)，实施顺序见 [任务清单](tasks.md)。

## 2. 阶段目标

让登录用户能够建立或加入研究空间，并保证以后所有自选股和观点数据都以空间为边界进行隔离。

## 3. 本阶段范围

- 查询当前用户加入的空间；
- 创建研究空间；
- 选择或切换当前空间；
- 生成、停用和使用邀请码；
- 查看空间成员；
- 按最终确认的权限管理成员；
- 成员主动退出规则；
- 非成员访问、跨空间访问和重复加入防护；
- 前端接入真实空间数据和完整状态反馈。
- 分层判断账号与空间身份：独立治理账号为 `SUPER_ADMIN`，普通账号可以建立空间成员关系；在某个空间内，当前所有者显示为 `OWNER`，其余有效成员显示为 `MEMBER`；
- 提供最小超级管理员能力：查看用户和空间基础信息、禁用或恢复用户、归档异常空间、查看自己的管理操作记录。

本阶段不包含股票、行情、观点、通知、Redis、MQ 和 Agent。

## 4. 已确认规则

| 编号 | 规则 |
| --- | --- |
| WS-001 | 系统支持多个相互隔离的研究空间，用户与空间是成员关系，不把固定家庭或人数写死。 |
| WS-002 | 用户通过受控邀请加入已有空间，不能由前端自行指定空间角色。 |
| WS-003 | 空间创建者、成员身份、角色和加入时间由后端产生或验证。 |
| WS-004 | 访问任何空间业务前，后端必须验证当前用户是该空间的有效成员。 |
| WS-005 | 修改 URL、请求参数或请求体不能绕过空间隔离。 |
| WS-006 | 同一用户不能在同一空间拥有两条成员关系，由数据库唯一约束兜底。 |
| WS-007 | `SUPER_ADMIN` 与普通账号类型互斥，超级管理员不能建立空间成员关系；普通账号在每个空间都先具有成员关系，再按是否为当前所有者显示为 `OWNER` 或 `MEMBER`。 |
| WS-008 | `OWNER` 管理自己当前拥有的空间（包括受让所得），`MEMBER` 使用已加入空间；V1 不增加空间 `ADMIN`。 |
| WS-009 | `SUPER_ADMIN` 可以管理账号状态和空间基础状态，但不能默认查看或修改成员观点、冒充用户或代替用户操作业务数据。 |
| WS-010 | V1 允许一个用户创建多个空间并加入多个空间，暂时不设置固定数量上限；后续出现真实滥用或运营需求时再增加限制。 |
| WS-011 | 空间名称在整个生命周期内保持全平台唯一；保存前删除全部 Unicode 空白字符，清理后限制为 1～30 个字符，除此之外不同大小写、标点或其他字符可以视为不同名称。 |
| WS-012 | V1 创建空间时用户只填写必填名称；创建者、创建时间、初始 `OWNER` 和空间状态由系统产生，不为页面显得丰富而增加没有明确业务用途的空间简介。 |
| WS-013 | 一个空间同时只允许一个有效邀请码；邀请码由安全随机数生成，为 6 位大写英文字母或数字，固定 7 天有效、最多成功加入 5 名成员，生成新邀请码时旧邀请码立即停用；完整邀请码只向当前 `OWNER` 展示，普通成员、超级管理员和历史邀请响应都不展示完整明文。 |
| WS-014 | 已是有效成员的用户再次使用邀请码时不重复创建成员关系、不消耗次数，提示后进入已有空间。 |
| WS-015 | `MEMBER` 可以主动退出，`OWNER` 可以移除普通成员；主动退出者可以使用有效邀请码重新加入，被移除者只能使用移除后新生成的邀请码重新加入。 |
| WS-016 | `OWNER` 可以把所有权转让给一名有效 `MEMBER`，确认后立即完成；创建者是不可变历史事实，当前 `OWNER` 是可转让的成员角色。 |
| WS-017 | 只有 `OWNER` 一人时不能直接退出活动空间；可以继续保留或归档空间。 |
| WS-018 | 空间不物理删除，只允许归档；归档空间保留历史、名称继续占用并停止新增或修改业务数据。 |
| WS-019 | `OWNER` 可以恢复自己主动归档的空间；由 `SUPER_ADMIN` 治理归档的空间只能由 `SUPER_ADMIN` 恢复。 |
| WS-020 | 登录后没有空间时显示创建或加入引导，只有一个有效空间时直接进入，多个空间时显示选择页；切换空间不改变成员关系。 |
| WS-021 | 前端选择目标空间后自动在页面和请求中携带空间标识，后端仍须逐次验证有效成员关系；失去访问权时清除当前选择并返回选择页。 |
| WS-022 | `OWNER` 负责空间资料、邀请、成员、所有权和归档治理；`OWNER` 与 `MEMBER` 在添加共享股票、改变共享状态和发表本人观点方面平等，任何角色都不能篡改他人观点。 |
| WS-023 | V1 只设置一名独立的 `SUPER_ADMIN` 治理账号，由开发者通过默认关闭、无公开入口的一次性初始化流程建立；公开注册只能创建普通用户，普通用户不能提升为超级管理员；该治理账号不能创建、加入或拥有研究空间。 |
| WS-024 | `SUPER_ADMIN` 禁用账号后，该账号的已有登录状态在下一次受保护请求时立即失效；账号历史数据和成员记录继续保留，恢复后可以重新登录。 |
| WS-025 | 成员主动退出或被移除后立即失去空间访问权，但已经发表的历史观点继续保留；重新合法加入后可以查看空间完整历史，包括本人以前的观点。 |
| WS-026 | 超级管理员后台使用独立入口，不混入普通空间设置；禁用用户和治理归档空间执行前必须二次确认，但 V1 不强制填写操作理由。 |
| WS-027 | 登录后一次只进入一个当前空间，不混合展示多个空间的业务数据；空间内部固定提供概览、共享自选、成员和设置四个主入口，空间切换返回独立选择页。 |
| WS-028 | 已归档空间在选择页独立展示并只读访问；当前空间失效时，前端清除选择、返回选择页并明确提示原因。 |
| WS-029 | 超级管理员后台分为用户、空间和操作记录三个职责区；治理页只展示运营所需基础信息，不展示观点正文等研究内容。 |
| WS-030 | `SUPER_ADMIN` 可以治理归档活动空间并恢复由超级管理员归档的空间；`OWNER` 主动归档的空间仍由该空间 `OWNER` 恢复，超级管理员不代替普通用户决定。 |
| WS-031 | 禁用用户和治理归档空间使用说明目标、影响、数据保留和恢复方式的确认弹窗；V1 没有批量危险操作，不要求手输目标名称或填写理由。 |
| WS-032 | 普通 `MEMBER` 可以主动退出活动或已归档空间；`OWNER` 不能直接退出，必须先在活动状态转让所有权。除成员退出和按归档来源恢复外，已归档空间不允许其他修改。 |
| WS-033 | 唯一 `SUPER_ADMIN` 不能禁用自己的账号。禁用普通账号不会自动转让或归档其拥有的空间，确认弹窗必须提示受影响空间数量；账号恢复后原成员关系和 OWNER 身份继续有效。 |

## 6. 权限矩阵

| 操作 | SUPER_ADMIN | OWNER | MEMBER |
| --- | --- | --- | --- |
| 查看系统用户和账号状态 | 允许 | 不允许 | 不允许 |
| 禁用或恢复用户 | 允许 | 不允许 | 不允许 |
| 查看全部空间的基础信息 | 允许 | 不允许 | 不允许 |
| 归档异常空间 | 允许 | 不允许跨空间操作 | 不允许 |
| 查看空间内自选股和观点 | 不允许，治理账号不能成为空间成员 | 允许 | 允许 |
| 修改空间资料 | 不允许，治理账号不参与空间业务 | 允许 | 不允许 |
| 生成或停用空间邀请码 | 不允许，治理账号不参与空间业务 | 允许 | 不允许 |
| 管理普通成员 | 不允许，治理账号不参与空间业务 | 允许 | 不允许 |
| 转让所有权 | 不允许，治理账号不参与空间业务 | 允许 | 不允许 |
| 归档或恢复自己管理的空间 | 不允许，治理账号不参与空间业务 | 允许 | 不允许 |
| 添加自选股、改变共享状态和发表本人观点 | 不允许，治理账号不能成为空间成员 | 允许 | 允许 |
| 冒充其他用户或修改其观点 | 不允许 | 不允许 | 不允许 |

表中的“允许禁用用户”不包括唯一超级管理员自己。普通用户在不同空间可以分别是 OWNER 或 MEMBER，也可以继续创建或加入其他空间；空间身份不是账号的全局角色。

这里的“空间基础信息”指空间 ID、名称、状态、创建时间和创建者等运营信息，不包括成员的观点正文等研究内容。

## 7. 用户流程

### 7.1 新用户进入工作台

1. 用户登录；
2. 系统查询该用户加入的空间；
3. 没有空间时，显示“创建空间”和“使用邀请码加入”；
4. 只有一个有效空间时直接进入；
5. 有多个有效空间时显示选择页，用户点击后进入；
6. 用户可以返回选择页切换空间，切换不等于退出成员关系。

### 7.2 创建空间

1. 用户填写空间名称；
2. 系统删除名称中的全部 Unicode 空白字符，校验清理后长度为 1～30 个字符并保证全平台唯一；
3. 系统创建空间并将当前用户设为初始 `OWNER`；
4. 创建空间与创建者成员关系必须形成一个完整业务结果，不能留下只有空间、没有创建者成员关系的半成品；
5. 创建成功后直接进入新空间。

### 7.3 邀请加入

1. `OWNER` 生成固定 7 天、最多使用 5 次的邀请码；
2. 一个空间只有一个有效邀请码，重新生成会停用旧邀请码；
3. 当前 `OWNER` 可以查看和复制当前有效邀请码；普通成员和超级管理员不能查看，历史邀请只展示生成时间、失效状态和使用次数，不返回完整明文；
4. 用户输入邀请码后，系统校验状态、有效期、使用次数、现有成员关系和此前移除时间；
5. 已是成员时不重复加入、不消耗次数并进入空间；
6. 新成员加入成功必须同时满足邀请码次数更新和成员关系写入成功，失败时不能留下半成品。

### 7.4 切换、退出和移除

- “切换空间”只返回空间选择页，不改变成员关系；
- `MEMBER` 主动退出后返回选择页，并可通过有效邀请码重新加入；
- `MEMBER` 即使处于已归档空间也可以主动退出，因为这是管理自己的成员关系，不是修改空间研究内容；
- `OWNER` 移除普通成员后，该成员立即失去访问权；
- 被移除成员不能使用移除前已经存在的邀请码重新加入；
- “退出空间”和“退出登录”是不同操作，页面必须使用明确文案并对退出空间进行确认。

### 7.5 所有权转让与归档

- `OWNER` 可以选择一名有效 `MEMBER`，确认后立即转让所有权；
- 转让后原 `OWNER` 变为普通 `MEMBER`，可以继续留在空间或主动退出；
- 只有 `OWNER` 一人时不能直接退出活动空间；
- 归档空间进入只读状态，在“已归档空间”区域保留历史；
- 已归档空间除普通 MEMBER 主动退出和合法恢复外，不允许改名、邀请、移除、转让或新增修改研究数据；
- 归档状态直接决定谁能恢复：`ARCHIVED_BY_OWNER` 由当前 OWNER 恢复，`ARCHIVED_BY_SUPER_ADMIN` 只能由超级管理员恢复。

### 7.6 页面进入与失效处理

- 登录后没有有效空间时进入创建或加入引导，只有一个时直接进入，多个时先进入选择页；
- 系统一次只展示一个当前空间，空间内主入口为概览、共享自选、成员和设置；
- 概览负责真实摘要、近期动态和快捷入口，不复制成员治理或股票添加业务；
- 已归档空间在选择页单独展示，进入后只读查看历史；
- 当前空间因退出、移除、归档治理或账号状态变化而不可访问时，前端清除当前选择、返回选择页并显示明确原因，不显示空白页或持续重试。

### 7.7 超级管理员治理

- 超级管理员后台位于独立入口；`SUPER_ADMIN` 登录后进入治理后台，不能作为普通空间成员使用工作台；
- 用户治理列表至少展示用户 ID、用户名、昵称、账号状态、注册时间和加入空间数量；详情可以查看所属空间、空间角色和成员状态，不显示观点正文；
- 空间治理列表至少展示空间 ID、名称、状态、创建者、当前 `OWNER`、成员数量和创建时间；归档状态直接显示由 OWNER 还是 SUPER_ADMIN 归档，可以查看成员基础身份、角色和状态，不显示股票与观点内容；
- 超级管理员可以禁用或恢复账号、治理归档异常活动空间，并恢复由超级管理员归档的空间；不能编辑密码、直接修改空间角色、冒充用户或物理删除真实数据；
- 超级管理员不能禁用自己的唯一治理账号；禁用 OWNER 不自动改变其空间、成员和所有权，其他有效成员仍可使用活动空间的共享研究功能，但 OWNER 治理能力要等账号恢复，超级管理员仍可另行治理归档异常空间；
- 操作记录按时间展示当前超级管理员执行的操作时间、类型、目标、操作前后状态和成功或失败结果；V1 不做复杂日志分析与导出；
- 禁用用户和治理归档空间前显示二次确认，清楚说明目标、影响、历史数据保留和恢复方式，不要求手输名称或填写理由。

## 8. 必须覆盖的失败情况

- 未登录访问；
- 非成员读取或修改空间；
- 使用不存在、过期、停用或达到次数上限的邀请码；
- 重复加入同一空间；
- 无权限用户生成或停用邀请码；
- 无权限用户移除成员；
- 创建全平台重名空间；
- 被移除成员使用移除前的邀请码重新加入；
- `OWNER` 未转让所有权就退出活动空间；
- 非法转让给非成员或无效成员；
- 对归档空间继续执行新增或修改；
- 前端保存的当前空间已经失去访问权限；
- 并发使用邀请码时超出最大使用次数；
- 多步写入失败时出现半成品数据。
- 唯一超级管理员尝试禁用自己；
- 向已退出、被移除或账号已禁用的成员转让所有权；

具体响应码和错误结构属于技术设计，不在本文件重复。

## 9. 阶段验收标准

本阶段验收至少包括：

- 真实用户可以完成创建空间和邀请码加入闭环；
- 用户可以按 0 个、1 个和多个空间的规则进入、选择并切换空间；
- 成员列表与角色真实来自后端；
- `MEMBER` 可以主动退出，`OWNER` 可以移除成员并完成所有权转让；
- 归档空间只读保留，且恢复操作符合 `ARCHIVED_BY_OWNER/ARCHIVED_BY_SUPER_ADMIN` 状态；
- 非成员和跨空间访问被后端拒绝；
- 重复加入、失效邀请码和无权限操作有明确响应；
- 创建和加入流程的事务失败不会留下半成品；
- 数据库唯一约束和权限测试形成可复现证据；
- 前端覆盖加载、空数据、成功、业务失败、网络失败和无权限状态。
- 0 个、1 个和多个有效空间以及已归档空间分别进入正确页面，不混合展示跨空间业务数据；
- 当前空间访问权失效后能够清除选择并返回选择页，同时向用户说明原因；
- 超级管理员后台的用户、空间和操作记录页面只展示允许的基础信息，危险操作确认和按归档状态恢复的规则符合已确认要求。
