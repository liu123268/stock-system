# 文档职责与教学材料维护

场景读取和新规则处理见 [规则入口](project-rules.md)。本文件只规定文档内容边界和材料准入。

## 唯一正文与派生视图

| 内容 | 正文位置 | 其他位置的边界 |
| --- | --- | --- |
| 当前状态 | `status.md` | tasks 保留逐项证据；README 只放一句进度并链接 |
| 当前阶段需求／技术方案／实施证据 | 对应 specs 的 requirements／design／tasks | 分别回答做什么／怎样做／做到哪里；用规则编号关联，不复制整段 |
| 已实施数据模型 | Flyway 可执行结构、`architecture/data-model.md` 建模理由 | 阶段 design 只说明该流程怎样用表，不复制字段表 |
| 技术 | `architecture/technology-stack.md` 实际采用；`technology-reference.md` 原始学习输入 | 输入不是实施命令；原始文字不得改写或删减，应用分析只链接实际状态 |
| 工程教学 | 对应 engineering 文件；认证教学在 `architecture/authentication.md` | 解释原代码、变更和数据流；不另建重复 learning 目录 |
| 产品目的、视觉、面试 | product-principles／ui-design-system／career | PRODUCT 是工具摘要，README 是公开摘要，HTML 地图是展示快照；均不新增独占规则 |

README、PRODUCT、功能地图、面试和亮点材料只在面向读者的信息或里程碑变化时更新。允许最少背景便于独立阅读，完整过程和数值证据使用链接；它们不成为开发前必读项。

## 日常维护

- 精简重复表达，不以缩短篇幅为由删除已有的重要要求、产品决定、教学、Bug 或面试内容；合并时保留独有信息和可找到的入口。
- 确认需求就写 requirements，确认方案就写 design，验证完成就写 tasks；不要等下一次对话或用户提醒。
- 已有教学段落按主题修改，不随每次 CODE 追加相同概念。历史方案必须注明已替代，不能用“现在”描述旧实现；最新代码教学与历史复盘分清。
- 每完成一个已验证的纵向闭环、重要技术接入或里程碑，AI 不等待用户提醒，主动检查工程教学、重要 Bug 复盘、项目亮点和分领域面试问答是否需要同步；没有新增知识或证据时不机械追加重复内容。
- 不创建空标题文档、无意义的跳转文件或重复目录；删除文件先迁移独有信息并修正全部引用。导航只在结构变化时更新。
- 普通文档修改检查受影响文件及引用；结构大改可用 [文档检查脚本](../../scripts/check-docs.py) 检查本地链接并统计默认读取体积。统计不作为删减重要内容的硬门槛，脚本也不能证明自然语言没有语义冲突，仍需审阅相关规则。
- 开发库版本、当前进度、最新验证集中在 status，且标明验证日期。目录与模型只描述稳定结构，不各自保存一份环境状态。

## 交接内容与交接要求

`status.md` 承担当前交接：做到哪里、阻塞与未完成事项、最近验证、下一步及相关任务链接；稳定环境链接 development，详细证据链接 tasks，不复制全部历史。

用户对交接的写法、保留内容或更新方式提出长期要求时，在本节修改对应要求；本次进度写入 status。更新进度不能覆盖长期要求，也不能只在聊天或某次交接快照里记录要求。接手时通过项目入口和场景路由找到它们，不要求用户重述。

## 重要 Bug 准入

根因不直观且有教学价值，涉及框架、权限、事务、并发、缓存或部署，可能复发，对多个模块或用户数据有影响，或能形成有价值的面试追问时，才建立 `engineering/bugs/BUG-三位编号-简短英文主题.md`。

内容包括现象、影响范围、排查、根因、修复、验证、预防和面试转化。预防要求若已在测试或开发规则中生效，引用对应章节，不复制另一套执行规则。普通小错误不单独建复盘。

## 面试与亮点

- 重要概念随实现沉淀在工程教学中；阶段或里程碑结束后，把已实现、已验证的能力转成 career 中的问答与亮点。
- 面试问答只承载能够形成稳定问题的真实项目经验：已实现并验证的技术取舍、数据流、失败边界，或已经实际发生且完成修复的重要 Bug。它不是进度文档，不逐项记录“尚未接入什么”或下一步准备开发什么；当前进度只见 `status.md` 和对应 tasks。
- 为解释取舍确需交代早期状态时，明确写成“历史背景”，随后说明代码怎样演进以及证据在哪里，不能把会过期的阶段状态写成答案结论。尚未实现的候选架构不得提前包装成面试亮点。
- 不建只负责跳转的面试索引；按技术领域拆完整问答，文件名为“序号 + 领域”，问题使用稳定领域编号，如 SEC-01、DB-01。
- 答案包含项目场景、完整回答、代码或测试证据、可能追问、当前边界；已有详解使用链接，不再复制排查全过程。
- 文件过长按知识边界拆，不建无意义的 part-2、part-3。候选技术、历史包体积或未复现性能不能冒充当前成果。
