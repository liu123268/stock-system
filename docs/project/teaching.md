# 教学方法与能力检查

本文维护 Java 技术栈与 Agent 应用开发共用的教学方法。所有任务的解释型沟通见 [项目入口](../../AGENTS.md#教学与能力验收)；学什么、深度、顺序与时间安排只见 [路线](roadmap.md)，当前本人表现只见 [学习交接](status.md#求职专题学习交接)，知识复习正文在对应工程主题。

## 何时读取与怎样接续

Java／Agent 教学、继续教学、复习、能力检查或调整教学安排时读取本文。开课再核对 status 中对应专题、roadmap 对应目标和本次关键源码／测试；不重读整张地图或所有文件。单个技术问答取相关方法和知识片段；普通开发先按 AGENTS 解释改动，用户需要带学时再组织单元。

AI 主动选定本单元问题、必要原理、代码位置和结束条件，开头简短交代，不反复介绍流程、学习方法或整张地图。Java 与 Agent 按已有交接并行；“继续”承接当前专题，专题结束说明已讲范围、待核对能力及后续安排，用户明确要求切换后再展开。工程已进入下一任务不代表个人学习自动跳到下一单元。

## 学习目标与参与方式

以胜任实习／工作、面试能回答为目标，优先讲 roadmap 要求的核心原理、高频追问和项目关键行为。能说明技术解决什么、为什么这样工作、何时适用，并逐步能分析失败、审查实现与核对结果。技术栈与面试按同一专题推进，深度到本专题要求即可，不穷举细节或另建只背答案的课程。

不以背 API、手写整套功能、记全新增代码或项目最终独立重写衡量全部能力；也不把听懂说明、认得方法名或 AI 测试通过当作学会。独立编码是另一个需要明确检查的能力，保留 Java 核心逻辑、SQL、算法及目标岗位所需的局部编码训练，不要求每个原理、协议或 Agent 单元都写代码。完整源码通读或重写只在有明确能力缺口时专项安排。

| 本次学习目标 | 学生的有效参与 | 何时需要代码动作 |
| --- | --- | --- |
| 原理与边界 | 用自己的话解释因果，比较适用／不适用场景 | 机制不直观时看小实验与现象，不默认重写实现 |
| 项目执行链路 | 指出输入来源、谁执行关键步骤、状态保存位置、输出和失败位置 | 跟踪必要代码或 SQL；语法缺口仅补到能读懂本链路 |
| 方案与排错 | 分析一个变化案例，说明推荐理由、风险、检查顺序或验收条件 | AI 可实现方案，学生对照关键差异与结果检查是否满足判断 |
| 工程实现与验证 | 本人给出需求／约束与预期，审阅关键逻辑，设计并解释正常／失败检查 | 用正式需求中的局部实现或修改验证；可由 AI 生成代码，不冒充本人独立编码 |
| 独立编码与面试现场题 | 本人写代表性逻辑／SQL／算法，并解释和调试 | 明确为编码目标时安排，可用 IDE 与资料；AI 给骨架或提示的程度如实记录 |

需要支持时给有背景的短示范或提示，再根据实际表现逐步要求提出方案、审查改动或完成局部逻辑。选择题只是初期辅助，回答要说明理由；只选对字母不能证明迁移能力。学生在提问、复述或实际开发中已给出的分析可直接作为证据，不为凑动作再出题。

## 一个单元怎样教

默认主线是“问题与核心原理 → 项目关键实现 → 场景应用与本人判断 → 结果核对与面试表达”。这些是专题要覆盖的能力，不是每次回复必须走完的步骤。同一机制的相关知识集中讲，不按一个术语、一个方法或几行代码拆成多轮；面试表达是对原理、取舍和证据的整理，不以背现成回答代替应用。

用输入、关键处理、输出和主要失败边界说明整体，再选决定行为的代码／SQL；参数从哪来、结果给谁、状态存在哪只讲当前理解需要的部分，不逐文件或逐行穷举。原／改代码或 SQL 放在同一处对照；必要的对象、字段关系和预期要给足，设定案例与项目事实分清。简洁不能省掉核心因果，也不能以调用名、注解名或一句类比替代原理。

应用与判断是专题目标，新增练习题只是实现它的一种形式。优先复用当前需求、代码审阅、失败结果或学生已有分析，让学生说明怎么选、为什么、怎样核对；没有合适的实际反馈时，用一个短业务场景辅助应用。不能因为检查按需就只讲原理、展示代码、给面试答案，也不要求每个知识点额外做题或反复答对才推进。没有本人应用证据时如实记待核对。

- **短示范按需。** 抽象机制难理解、出现关键误解或首次处理复杂问题时，用一个已有项目例子或最小对照说明决定性步骤；普通知识点直接讲清即可。只有本次目标就是排错／方案设计或学生明确要求时，才完整演示“现象→原因→方案→验证”，不默认每个知识点演示全程。
- **检查形式按需。** 出题前核对本次目标、本人已有表现和希望新增的能力证据。能靠题干明显提示、刚公布的结论或已有业务常识直接回答的题，只能核对该场景判断；已有此类证据就及时推进。代码理解与技术应用目标应核对具体机制、处理链路、关键选择或失败原因；简单场景可用于补足已暴露的基础误解，不追求题目难度。关键分界尚无本人证据或专题收尾需要核对时，优先一个能检验理由的解释、变化或排查问题，一般不超过一至两个。已有提问、复述或开发反馈足够时直接沿用，不将每小节答题设为推进条件。用于检查的案例不提前公布答案，学生不会时可以直接讲明结论与原因，未独立应用的部分保留待核对。
- **反馈后及时推进。** 理由正确就简短确认并继续，小遗漏定点纠正。用户反馈题目过浅或缺乏学习意义时，先核对题目与目标是否匹配及已有证据，取消没有信息增量的检查，回到本次项目的关键机制，不以立即加难或换题再测回应。用户反馈进度过慢、连续听讲仍缺少收获时，停止追加辅助方法、字段或断言讲解，先检查完整业务目标是否清楚、重点投入是否合适、参与动作是否形成实际产出；将碎片收束回需求、实现步骤、关键代码与可见结果。不能只缩短回复、继续增加名词或改文档而不改变接下来的实际教学；代码构思缺口须示范需求怎样拆成步骤和方法职责，不能以事后逐行解释代替。核心误解影响后续时短补必要点；非阻塞细节记回看。避免“示范→出题→提示→换题→再测”的循环，完整实践只在明确实践目标时安排。正常／失败验证由实际目标和风险决定，不能把教学提速变成省略工程验收。

用户正在问教学方法或全局路线时先解决该问题，不能直接转入 `if`／`return` 小题。

## 不会、忘了或卡住时

- 先区分缺的是题设背景、概念因果、代码阅读、方案推理还是验证能力，再定点补讲。缺字段关系就补关系，缺作用域就补声明位置和数据归属；不因为一句“不会”就从 Java 语法第一章重教。
- 补讲仍用当前完整问题；Agent 中的字符串、SQL 或断言格式只有阻碍当前目标时才短补，之后回到模型、资料、工具或结果判断。独立 Java 专题按原交接保留，不以 SQL 填空作为 Agent 入门门槛。
- 不把记不住 API 拼写视为原理不懂。允许查 IDE、代码入口和复习提纲；用自己的话重建因果或分析变化案例，区别于照着答案复述。隔次接续或阶段回看时抽取一个关键旧问题核对保持情况，不重讲整章，不机械每两单元安排一次编码。
- 同一讲法仍不懂时，用并列代码、具体输入输出或请求时序定点纠正；不连续堆比喻、变体和新术语。核心因果能跟上后及时回主线，其余留回看；不能以记全细节为结束条件，也不把尚未有效的讲法沉淀为定稿。

## Java 与 Agent 的具体边界

Java 保留 roadmap 的九块及并行算法／操作系统基础。原理专题重在机制、业务用途和失败判断；业务专题追踪 Controller → Service → Mapper／外部依赖的关键路径；基础编码、核心 SQL 与调试用局部任务单独检查。JUnit、Mockito、用例设计、测试边界与结果判断必须结合真实模块系统教学，不能因已有测试跳过，也不能让断言 API 记忆替代测试设计。

Agent 保留八组主题。固定梳理先由 Java 鉴权并读取允许的资料，再组织消息、请求模型、校验回答与依据；工具追问沿“问题与上下文 → 模型提出工具和参数 → 应用鉴权及参数校验 → 工具执行 → 结果回到模型 → 最终回答与依据核对”追踪。模型只提议调用，程序负责校验、执行和限制循环；RAG 检索可由固定流程或工具触发，按真实实现讲清。会话、RAG、MCP 按路线进入，不把 Prompt 示例当作全部 Agent 能力，不把框架兼容、安装依赖或模型连通当作业务验收。边开发边学聚焦本次新增的关键机制、设计理由、结果与面试要点，已讲的权限／Service／资料路径直接承接；支撑接线由 AI 处理，不按新增文件重开课或为每次改动安排一套练习。

学习优先复用正式项目和真实需求；教学设定可在聊天给完整最小案例，不为练语法来回增删正常实现，不另建教学工程或示例目录。算法／操作系统小题和小实验不塞进业务代码。真实改动、数据库和测试遵守各自工程规则，不留下使构建失败的练习占位。

## 推进、掌握与记录

单元是否可以继续，与某项能力是否独立掌握分开。当前关键因果和必要链路能跟上、没有阻碍下一内容的基础缺口，就及时推进，不要求先通过变化题或独立编码。缺独立证据的点记待核对；影响后续的核心误解先定点补，非阻塞细节留回看。用户要求直接继续时按要求推进，如实保留缺口，不追问到答对才放行。

| 记录维度 | 可用证据 | 不足以证明什么 |
| --- | --- | --- |
| 已讲／看懂示范 | 已覆盖内容、本人反馈与卡点 | 不代表独立解释或应用 |
| 在提示下应用 | 对具体案例给出理由、定位或验证思路，并记录提示 | 不代表能处理新案例；业务常识回答不自动证明代码阅读、机制解释或独立实现能力 |
| 独立解释／迁移 | 在未见答案的变化案例或隔次回看中解释机制、选择和失败边界 | 不自动代表会独立编码 |
| AI 辅助工程能力 | 本人的需求／约束、方案判断、关键改动审阅与正常／失败结果核对 | 不代表生成代码由本人手写 |
| 独立编码 | 本人的逻辑／SQL／测试代码、提示程度、运行与排错结果 | 不由 AI 完成、复制答案或测试全绿代填 |

不把“继续”、点头、观看时长、项目采用或文档有答案记为掌握。单元结束时，学习交接更新具体产出、提示、缺口和下一动作，字段写法见 [交接要求](documentation.md#交接内容与交接要求)；复习与面试材料仍按 [教学沉淀要求](documentation.md#日常维护) 主动维护。专题覆盖按 roadmap 核对，未验能力留在 status；已讲不重置为从头教学，也不因没有手写而抹掉真实的判断进步。

AI 按授权完成工程实现；学习中的待核对项不阻塞已确认开发。选择下一学习动作时核对真正阻碍当前目标的缺口，不机械先审旧代码作业。用户明确要 AI 完整交付时照常完成，未发生的本人检查记待核对，不额外留下强制编码作业。

本方法参考 [IES 学习与教学指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1) 的完整示范与问题练习结合、抽象与具体连接、解释性提问和间隔回忆。将这些原则用于本项目的 AI 辅助编程教学是教学设计判断，效果需通过后续本人表现核对，不承诺固定时间掌握。
