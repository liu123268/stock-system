# 项目开发路线

更新时间：2026-09-29

本文件描述从当前状态到可演示、可写入简历版本的阶段顺序。技术真实状态见 [项目实际技术栈](../architecture/technology-stack.md)，当前正在进行的工作见 [当前项目状态](status.md)。

## 路线原则

开发节奏、准入和技术学习执行要求见 [工作流](workflow.md)，本文件只维护跨阶段顺序与进入条件。

## 实习准备与阶段关系

当前目标是 Java 后端实习。产品功能完成、代码验证通过和个人掌握程度分别判断；功能完成证据见 specs，学习目标对照 [技术参考](technology-reference.md)，不能用任务勾选推断用户已掌握。

开发主线先收口已确认的 Java 核心 V1，再增加单 Agent；求职准备从现有真实闭环开始，与开发并行，不等待下面所有阶段结束。Java 核心版可以作为阶段性简历与演示材料，尚未完成的功能如实注明；最终展示版仍保留已确认的单 Agent 目标。

| 优先方向 | 从现有项目切入 | 可检查的准备结果 |
| --- | --- | --- |
| 核心业务与 Java 基础 | 登录鉴权、空间隔离、加入股票事务、研究周期；结合集合、异常、代理与 Spring 请求链路 | 能脱离现成答案讲清请求到数据库的过程，解释失败边界，并独立完成关键逻辑的小练习 |
| MySQL 与并发 | 邀请次数竞争、唯一约束、行锁、观点分页 | 能写核心 SQL、解释事务与锁；完成一次带数据规模、执行计划和前后对照的真实 SQL 优化实验，不编造提升比例 |
| Redis 与外部依赖 | 行情缓存、同 Key 回源合并、超时及故障降级 | 能说明 Key／TTL、数据库与行情来源的区别、锁的适用边界，并用已有测试解释失败场景 |
| 测试与交付 | JUnit／Mockito、真实 MySQL 集成测试、启动配置与部署 | 能独立设计正常和失败用例、判断测试证明了什么；完成可复现启动、环境配置与排错演示 |
| 基础与面试表达 | Java／JUC／JVM、网络、操作系统、数据结构算法和 Hot100；对应项目问答 | 按原技术目标持续练习；项目里没有的基础可做小实验，明确标为知识准备，不强塞业务实现；练习项目介绍、技术追问与现场编码 |

以上是准备方向和验收方式，不是已完成清单，也不另开一套与项目专题重复的课程。SQL 实验承接阶段 4，交付承接阶段 5，简历与复述承接阶段 7；具体证据仍放唯一工程／career 落点。

新增产品增强优先核对是否能补足上述能力缺口；现有场景足以练习时先吃透现有实现。MQ 仍保留“掌握一种、真实异步场景”的学习目标，主项目尚无合适场景时暂不接入；更复杂图表、额外市场、微服务、RAG／MCP 和多 Agent 不成为开始求职准备的前置条件。

## 阶段 0：产品与工程基线

目标：开发前先统一名称、需求、角色、文档、规则和技术路线。

- 建立 `AGENTS.md` 项目规则入口与按场景读取机制；
- 整理交接、进度、规则、技术栈、Bug、面试和亮点文档；
- 收集并分析用户技术学习参考；
- 确定暂定名称并在正式发布前完成最终命名；
- 确认 V1 角色模型和功能边界；
- 评估 Spring Boot 维护版本；
- 确认单 Maven/Spring Boot 工程内按业务模块分包，并规定模块依赖与命名边界；
- 明确每阶段验收标准。

完成条件：新对话能够自动接手，文档无失效链接，技术参考与实际技术栈清楚分离，下一阶段需求可以直接实施。

## 阶段 1：研究空间最小闭环

目标：建立所有后续业务的数据隔离和权限基础。

- 查询当前用户加入的空间；
- 创建研究空间；
- 当前空间和空间切换；
- 生成、停用和使用邀请码；
- 成员列表和成员状态；
- 空间外个人资料入口、修改昵称和登录后修改密码；
- 根据有效成员关系和 `workspace.owner_user_id` 判断 OWNER/MEMBER，并落实每项操作规则；
- 最小超级管理员用户、空间状态和操作记录治理仍是 V1 必需范围，但调整到股票与多人观点核心闭环之后收尾，不在此阶段扩展额外后台能力；
- 非成员访问、跨空间越权、重复加入和事务回滚测试；
- 前端接入真实空间数据。

重点能力：关系建模、RBAC、事务、唯一约束、幂等、越权防护和集成测试。

当前详细范围、设计和实施顺序见 [SPEC-001 研究空间规格](../specs/001-workspace/requirements.md)。

阶段衔接：空间访问和归档边界可用后，进入 [SPEC-002](../specs/002-stock-research/requirements.md) 的股票与初始观点闭环；真实 pull 行情正确性闭环之后，验收 Redis 共享缓存及故障降级，再进入研究生命周期与多人观点时间线，随后返回个人资料、空间改名和超级管理员最小治理。当前具体任务与阻塞只见 [status](status.md)，不在路线保存另一份下一步。Redis 不与 WebSocket/SSE 捆绑实施；目录完整性、每日同步与部署可靠性按 SPEC-002 任务分别验收，不把它们隐含为行情页面完成的结果。

## 阶段 2：股票与行情闭环

目标：让成员通过标准股票数据建立共享自选股，并在首次添加时同时发表初始观点，形成用户可见的第二段核心闭环。

- 验证合法、稳定的 A 股与港股数据提供者；
- 定义 `MarketDataProvider` 适配接口；
- 股票基础信息同步和搜索；
- 最新可用价格与行情时间；
- 基础报价先完成批量、限流和进程内短缓存，再接 Redis 共享层；完成度只见阶段 tasks，不在路线保存另一份验收状态；
- 缓存 Key、TTL、数据库一致性、穿透/击穿/雪崩防护和 Redis 不可用时的降级边界，以 [SPEC-002 设计](../specs/002-stock-research/design.md#46-redis-共享行情缓存与访问保护) 为唯一正文；
- 添加共享自选股和初始观点的事务；
- 同一空间同一股票防重复；
- 行情失败和模拟数据标识；
- 自选股列表和状态筛选。

重点能力：第三方 API/sidecar 适配、Redis 共享缓存、限流与故障降级、数据来源可信性、事务和组合唯一约束；动态推送仍在有真实需要时再验证 WebSocket/SSE。

## 阶段 3：多人观点与复盘

目标：形成项目区别于普通股票 CRUD 的核心功能。

- 初始观点和后续观点更新；
- 作者与时间由后端产生；
- 多成员观点时间线；
- 股票详情、最新行情和关注以来表现；
- 简单历史走势；
- 观点撤销或状态变化，不物理覆盖历史；
- 近期观点动态和空间概览。

重点能力：时间线建模、审计性数据、分页查询、前端状态管理和可视化。

任务承接：研究生命周期由 SPEC-002 PLAN-207 跟踪；时间线规模、近期动态与详情行情／价格变化分别由 CODE-209～211 承接。它们与返回 SPEC-001 的账号／治理收尾共同构成 Java 核心 V1，不能因时间线页面可用就宣称阶段 3 或 V1 已全部完成。

## 阶段 4：性能、并发和可靠性

候选内容：

- 在阶段 2 已接入的 Redis 行情缓存上补充容量、淘汰、热点 Key 和更大规模故障演练；
- 登录失败限制或接口限流；
- MySQL 组合索引、覆盖索引、`EXPLAIN` 和慢 SQL；
- 定时行情同步和重复执行防护；
- 在业务阶段已有正确性保护上补更大并发的性能实验；重复添加、邀请码次数和旧页面误操作等正确性问题不得推迟到本阶段；
- 可复现的性能测试和基线数据。

引入条件：核心业务链路先正确运行，并且每项优化有可测量的目标和前后证据。

## 阶段 5：异步、可观测性和交付

Java 核心交付与后续增强分开安排：可复现启动、部署配置、日志排错、备份恢复说明及 CODE-206H 环境验收先服务于核心版演示；MQ 与更完整监控按真实问题逐项推进，不把全部候选中间件列为核心版交付前置。具体技术状态见实际技术栈。

交付与增强内容：

- 在 RocketMQ 与 Kafka 中评估并只选择一种 MQ，处理非核心动态、通知或数据同步；
- 消息幂等、重试、死信和失败补偿；
- Actuator 健康检查；
- 结构化日志、请求追踪 ID 和关键指标；
- Docker Compose 统一必要服务；
- Nginx 托管前端和反向代理；
- 配置环境变量化；
- 部署、备份与恢复说明。

不为了展示消息队列而把强一致核心事务错误地异步化。

## 阶段 6：Java Agent 增量

目标：在完整 Java 业务系统之上增加可控、可追踪、可测试的 Agent 能力，使其成为“Java 后端 + AI Agent 应用工程”项目，而不是独立聊天 Demo。

实施顺序：

1. 直接调用 LLM API，完成结构化观点摘要，验证模型、成本、超时和输出校验；
2. 使用 Spring AI 建立单 Agent Tool Calling 闭环；
3. 只开放只读且带权限校验的工具：查询当前空间自选股、最新可用行情、历史行情和观点时间线；
4. 输出带数据来源和行情时间的观点对比、风险清单与待验证问题；
5. 增加会话状态、调用次数上限、超时、重试、Token/成本统计、链路追踪、测试集和回归评估；
6. 有真实研究文档检索需求后再加入 RAG；需要与外部工具形成标准协议时再加入 MCP；
7. Multi-Agent、模型训练、自动荐股和自动交易不进入这一阶段。

完成条件：Agent 复用真实 Java Service 和当前用户权限，模型不能直接访问数据库或任意接口；工具调用和最终回答可以追踪，关键问题有稳定测试集，失败时不会写入错误业务数据。

## 阶段 7：简历、面试和演示交付

本节是贯穿开发的交付清单，不表示必须等阶段 6 完成才开始准备。每个可验证闭环先形成可讲述的材料，Java 核心版和后续 Agent 版分别更新；性能报告只有完成实际实验后才能作为成果，未完成时保留缺口。

- README 项目介绍、架构图、ER 图和截图；
- 一键或可复现启动方式；
- OpenAPI 接口文档；
- 核心测试结果；
- 索引和性能实验报告；
- 已验证项目亮点；
- 分领域完整面试问答；
- 3 分钟项目介绍和关键流程演示；
- 简历项目描述只引用已经验证的事实。
