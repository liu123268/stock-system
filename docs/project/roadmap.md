## 路线原则

开发节奏、准入和技术选型要求见 [工作流](workflow.md)，教学方式见 [教学方法](teaching.md)；本文件维护跨阶段顺序、进入条件、当前教学范围与具体能力目标。

## 实习准备与阶段关系

当前目标是 Java 后端实习。产品功能完成、代码验证通过和个人掌握程度分别判断；功能完成证据见 specs，学习目标对照 [技术参考](technology-reference.md)，不能用任务勾选推断用户已掌握。

2026-10-09 [岗位、面经与行业实践复核](java-agent-market-benchmark.md#5-2026-10-09-重新核查与计划对照) 后，主准备方向保持 Java 后端，包括 AI 业务团队；Agent 增量同时支持接受 Java 的应用工程岗位。明确要求熟练 Python／PyTorch、模型研究或高级平台内核的岗位须另查差距，不能宣称当前路线覆盖全部 Agent 职位。基础学习与 Agent 开发并行，不以把所有 V2 功能做完作为开始准备 Java 面试的条件。

开发主线以 [V1 Java 核心版](../product/requirements-v1.md) 的业务、权限和数据基础支撑 [V2 第一阶段单 Agent](../product/requirements-v2.md)，阶段准入只在 [V2 版本定位](../product/requirements-v2.md#1-版本定位) 维护；已确认的 V2 可与 V1 的非阻塞观察尾项并行，不能据此关闭尾项或把 V1 标成全部完成。求职准备从已有真实闭环开始，与开发并行；V1 可独立作为简历与演示版本，其他产品增强仍按候选清单评估。

| 优先方向 | 从现有项目切入 | 可检查的准备结果 |
| --- | --- | --- |
| 核心业务与 Java 基础 | 登录鉴权、空间隔离、加入股票事务、研究周期；结合集合、异常、代理与 Spring 请求链路 | 能脱离现成答案讲清请求到数据库的过程，分析需求变化与失败边界；核心逻辑的独立编码另用局部任务核对 |
| MySQL 与并发 | 邀请次数竞争、唯一约束、行锁、观点分页 | 能写核心 SQL、解释事务与锁；完成一次带数据规模、执行计划和前后对照的真实 SQL 优化实验，不编造提升比例 |
| Redis 与外部依赖 | 行情缓存、同 Key 回源合并、超时及故障降级 | 能说明 Key／TTL、数据库与行情来源的区别、锁的适用边界，并用已有测试解释失败场景 |
| 测试与交付 | JUnit／Mockito、真实 MySQL 集成测试、启动配置与部署 | 能独立设计正常和失败用例、判断测试证明了什么；完成可复现启动、环境配置与排错演示 |
| 基础与面试表达 | Java／JUC／JVM、网络、操作系统、数据结构算法和 Hot100；对应项目问答 | 按原技术目标持续练习；项目里没有的基础可做小实验，明确标为知识准备，不强塞业务实现；练习项目介绍、技术追问与现场编码 |

以上是准备方向和验收方式，不是已完成清单，也不另开一套与项目专题重复的课程。SQL 实验承接阶段 4，交付承接阶段 5，简历与复述承接阶段 7；具体证据仍放唯一工程／career 落点。

现有源码、业务场景和验收证据保留；“AI 实现＋解释＋测试”不能视为个人完成。V1 能力在 Java 专题及正式业务问题中核对；V2 重点围绕模型输入、输出约束、工具、会话、检索与评测。参与方式、基础补讲和推进判据统一沿 [教学方法](teaching.md)，MySQL、MyBatis 已讲内容按实际缺口回看。

V1 能力目标：能从请求定位 Controller→Service→查询；能分析需求变化应影响哪个条件／分支；能设计正常和失败用例、定位错误阶段；能解释权限、事务或缓存的放置理由。基础编码再检查本人能否完成代表性局部逻辑／SQL 与调试，不将其设为所有专题的共同入门条件；上面的 Java 后端准备方向和下面的系统教学范围保留，不让 V2 的新名词挤掉实习主线。

新增产品增强优先核对是否能补足上述能力缺口；现有场景足以练习时先吃透现有实现。MQ 仍保留“掌握一种、真实异步场景”的学习目标，主项目尚无合适场景时暂不接入；更复杂图表、额外市场、微服务、RAG／MCP 和多 Agent 不成为开始求职准备的前置条件。这里指可先用 V1 准备 Java 岗；完整 V2 的 RAG／MCP 仍须按 [第 6 阶段](#阶段-6java-agent-增量) 完成。

本学期选学安排为：Java 小业务能力与 Spring AI 单 Agent 并行，随正式项目中的模型接入、受限工具、会话、报告 RAG 和 MCP 功能推进学习；必要预检由 AI 作为工程准备处理，教学方式沿 [教学方法](teaching.md)。约三小时的框架视频只负责概念入门；用户当前不能自行选择补课专题或阅读官方 API 处理迁移，因此尚硅谷旧课移出本阶段默认学习安排，不将“自行按需补课”作为下一步。尚未掌握微服务时不把天机学堂整套工程列为紧接着的必修课。官方版本变化和课程核查见 [课程比较](java-agent-market-benchmark.md#6-课程核查与选学建议2026-10-09)。

开始投递不以“看完课程”或“全部 V2 做完”为判据：Java 岗先检查能否演示 V1、解释一条权限／Service／SQL 请求链、独立改一个小业务并排错，基础与算法按目标 JD 补缺；接受 Java 的 Agent 应用岗再检查能否亲手修改受限工具、展示真实模型调用轨迹、解释一个失败及修正，并按岗位核对 RAG／MCP 的具体要求。这些是准备检查，不是统一录用线；如实区分协作完成与个人独立能力，投递与继续完善项目可并行。

Python／LangChain 不作为开始上述投递的前置要求。本学期可先了解它们与 Java 框架的关系，正式进入该分支由明确的 Python 岗位硬要求、承担 Python Agent 服务或经验证的 Python 库需求触发；届时补 Python 方法、API 与独立工具／检索练习，不把会运行 Java Agent 当作已经熟练 Python。少量脚本学习与系统学习 Python Agent 工程分别判断。

### 岗位分流与学习优先级

2026-10-12 根据 [近期 Java／Agent 岗位再评估](java-agent-market-benchmark.md#8-2026-10-12-java-与-agent-岗位及教学地图再评估) 校准。下面是准备层次，不是市场占比、固定工期或录用保证；毕业届别、学历、实习出勤及岗位语言条件另核对。

| 准备层次 | 当前应形成的能力 | 与教学地图的关系 |
| --- | --- | --- |
| 两类岗位的共同底座 | 用 Java 的对象、集合与异常完成逻辑；能跟踪请求、写必要 SQL、校验权限、补正常／失败用例、检查日志与 Git 差异，并解释一次本人改动 | 九块按真实问题协同使用，算法／操作系统持续练；不是先背完九块才做业务 |
| Java 后端的深入准备 | 解释线程池、事务／锁、索引、缓存与外部失败；完成既有 SQL 优化、并发或缓存专题的一项独立验证 | 按现有 Java 交接补缺；MQ 与简单分布式等原始实践沿后续目标进入 |
| 接受 Java 的 Agent 应用准备 | 修改模型输入与结构化输出、受限工具、会话或检索的关键逻辑；追踪输入→调用→程序校验→资料／工具结果→停止／失败→引用及质量结果 | 沿阶段 6 的八主题和业务模块推进；一套框架、一个向量库及至少一个 MCP 实践保持完整目标 |
| 目标岗位的额外条件 | Python 为硬要求时补实际 Python API／工具实现；岗位要求前端时按“熟悉”或“了解”的具体深度核对页面／接口实践；指定框架、微服务或平台职责时另核差距；研究／训练／顶尖人才要求按岗位单独判断 | Spring AI 经验可以用于解释通用机制，不能冒充已用过岗位点名的另一框架；单体项目不能冒充微服务经验，能理解前后端数据流也不等于已满足前端开发要求 |

AI 辅助研发归入第 9 块：提出需求与约束、拆分任务、审阅生成逻辑及权限、设计验证、定位错误、说明本人判断和 AI 产出。能生成代码只是一个环节；验收要看到本人对结果质量的判断，不要求脱离 IDE 手写所有模板。

### Java 后端教学范围

2026-10-12 确认：本阶段 Java 后端系统教学限定为下面九块，数据结构算法与操作系统基础并行练习。取实习岗位的共同核心，用真实项目串联原理、代码／SQL、验证与面试表达，不逐个依赖名开课。本范围不重置既有教学进度；哪些已讲、哪些仍待独立练习只见 [学习交接](status.md#求职专题学习交接)。本节九块与 [V2 学习地图](#学什么学多少与学到什么程度) 的八组 Agent 共同作为每次新技术栈学习的起点；已确认的 Java 与 V2 Agent 两条主线按既有安排并行推进。

事实以 [pom.xml](../../pom.xml)、业务源码及 [实际技术栈](../architecture/technology-stack.md) 为准。当前主工程已升级，不能继续按旧 Spring Boot 3.2／Jackson 2 编写本项目示例；教学范围不随版本名增加课程。测试讲 JUnit Jupiter 的用例、断言与生命周期，实际依赖版本同样以技术栈为准。

范围经 [基础补漏](java-agent-market-benchmark.md#7-2026-10-12-java-后端教学范围复核) 及 [近期 Java／Agent 岗位再评估](java-agent-market-benchmark.md#8-2026-10-12-java-与-agent-岗位及教学地图再评估) 调整；调研日期、岗位资格、要求／加分和读取边界只在调研记录维护。原始长期目标仍保留在技术参考，当前深度以下面九块为准。

编号表示知识归属，不是从 1 到 9 线性重学的课表。方法、对象、集合与异常支撑局部实现，请求链／持久化／权限／缓存随业务串联；测试与工程贯穿，算法／操作系统并行。已有 MySQL／MyBatis 进度和当前 Agent 单元沿 status 承接。

深度分三层：核心实践要能在 AI 辅助下设计、审阅代表性实现并验证结果，基础编码目标另验本人逻辑；基础原理要能解释、判断适用边界和排错；后续提高要有进入条件与可检查产出。下面“必教”表示覆盖范围，不要求每个术语各写一份实现；尚未采用内容如实标为知识准备。

#### 1. Java 基础与集合

- 必教：类型、方法、参数传递、访问控制与 `static`／`final`；面向对象与接口；String 不可变性、包装类与装箱／拆箱；泛型与异常；`equals()`／`hashCode()`；List／Map／Set／Queue／Deque，ArrayList／HashMap／HashSet，集合结构、扩容、Hash 冲突与选型；Optional／Lambda／Stream；IO／NIO、资源关闭、序列化／JSON 基础；反射与注解；项目实际涉及的常见设计模式。
- 案例：接口与实现类的职责、行情集合与 DTO 转换、异常传播；结合 Provider／Adapter、策略与缓存装饰解释设计取舍，以实际代码为准。
- 深度：能选择集合、解释对象比较与错误传播、编写最小逻辑；不讲完整 Java 标准库，不读集合源码，不为讲模式强改业务。

#### 2. Java 并发与 JVM

- 必教：进程／线程；Thread／Runnable／Callable；`synchronized`／`volatile`；JMM／happens-before；CAS／原子类；ReentrantLock；ThreadLocal、线程复用时的清理与跨线程边界；ThreadPoolExecutor 参数、执行流程、有界队列／拒绝策略；ConcurrentHashMap；CompletableFuture；Semaphore；线程中断、超时与资源释放；JVM 内存区域、对象创建、类加载、GC／GC Roots、OOM／StackOverflow 与基本问题定位。
- 案例：[行情同 Key 请求合并](../../src/main/java/com/stock/system/stock/market/CachingLongbridgeMarketGateway.java)、[CLI JSON-RPC 请求与响应匹配](../../src/main/java/com/stock/system/stock/market/LongbridgeJsonRpcClient.java)、Longbridge 并发保护和数据库并发测试。区分生产 CLI 与本地 SDK 的传输实现，不把一条路径的机制套给全部环境。
- 深度：解释共享状态、可见性、竞争、任务完成与失败清理；AQS 的排队思想、G1／ZGC 的作用达到理解层，不读 AQS 源码，不做高级 JVM 调优，不宣称项目已使用或调优所有 GC。

#### 3. Spring 核心与 Web 开发

- 必教：IoC／DI／Bean、Bean 生命周期；Boot 启动、自动配置与条件装配；Profile／配置属性与配置覆盖优先级；Spring MVC 请求流程、Servlet／内嵌 Tomcat；Controller／Service 分层与参数绑定；Jakarta Validation；Filter／Interceptor 的职责与区别；全局异常；Jackson JSON 转换；AOP／动态代理；`@Transactional` 原理与失效。
- 案例：Vue → Axios → Tomcat／Servlet 容器 → Spring Security 过滤器链 → DispatcherServlet → Controller → Service → Mapper → MyBatis／JDBC → MySQL；返回时经 Jackson 转成 JSON。结合 [SecurityConfig](../../src/main/java/com/stock/system/config/SecurityConfig.java)、[全局异常处理](../../src/main/java/com/stock/system/common/exception/GlobalExceptionHandler.java) 和配置文件定位职责。
- 深度：能跟踪一次真实请求、解释 Bean 注入和代理边界；不学完整 Spring 生态，不读 Spring 源码。

#### 4. MySQL 与 SQL

- 必教：表结构与关系设计、主键／外键／唯一约束、字段类型；CRUD／join／子查询／聚合、分页与批量操作；InnoDB／B+Tree、聚簇／二级／联合索引、最左匹配、覆盖索引／回表、索引失效；`explain`、慢 SQL 定位与优化；ACID／隔离级别／MVCC；行锁／间隙锁／Next-Key Lock；乐观锁／悲观锁／死锁；redo log／undo log／binlog。
- 案例：空间、成员、邀请、股票、研究周期的表关系与联合唯一约束；`select ... for update`；拼音检索与索引取舍；一次真实 SQL 修改前后的执行计划与效果对照。
- 事实边界：现有搜索已经分析执行计划并决定暂不新增拼音索引；优化对照实验仍待完成，不能写成已经实现的性能成果。已讲内容承接原交接，不从头再讲。
- 深度：能写核心 SQL、判断索引和事务是否服务业务；不讲高级 DBA，不讲分库分表。

#### 5. JDBC、MyBatis 与数据库连接

- 必教：JDBC 获取连接、参数绑定、执行、读取结果与释放资源；DataSource／连接池／HikariCP；MyBatis 工作方式、MyBatis-Plus、BaseMapper／Wrapper／注解 SQL、动态 SQL；对象与字段映射、`null` 更新策略、N+1 与查询次数；Spring 事务边界；Flyway 迁移。
- 案例：登录查询、邀请锁定、目录批量导入；Mapper → MyBatis／JDBC → DataSource 借连接 → MySQL → 映射结果 → 归还连接。具体原理和代码位置只维护在 [MyBatis 复习](../engineering/mybatis.md)，不在范围清单重复整堂课。
- 深度：能说明 ORM、JDBC 与连接池各负责什么，并写最小查询／更新；不读 MyBatis 源码，不把 MyBatis-Plus 当成 SQL 的替代品。Web 主应用与目录命令的 DataSource 形式以实际实现分别判断。

#### 6. 认证与安全

- 必教：Spring Security 过滤器链／SecurityContext；认证／授权；JWT 结构、签名、过期与 JJWT；BCrypt／Salt；哈希、加密、编码的区别；无状态会话；Cookie／Session／JWT 及存储取舍；401／403；CSRF／XSS 基础；OAuth2 的角色与授权思想；密钥和敏感配置管理；空间 OWNER／MEMBER 业务权限。
- 案例：登录、过滤器恢复身份、Service 校验空间权限、旧凭证失效；实际链路见 [认证与安全](../architecture/authentication.md)。
- 深度：能解释身份从哪里来、哪些校验在过滤器或业务层完成及失败结果；区分本应用 JWT 登录与供应商 OAuth 授权，CSRF 风险按凭据携带方式判断；不把空间角色夸大为完整通用 RBAC 系统，不开发完整 OAuth 授权服务器。

#### 7. Redis 与缓存

- 必教：String／Hash／List／Set／ZSet；TTL；缓存设计／Cache Aside；穿透／击穿／雪崩；热点 Key／Big Key；数据库与缓存一致性；本地与 Redis 多级缓存；同 Key 请求合并；分布式锁、`set nx`、锁所有权、Lua 安全解锁；RDB／AOF、内存淘汰；Redis 故障降级。
- 案例：[共享行情缓存与锁](../../src/main/java/com/stock/system/stock/market/RedisMarketSharedCache.java) 及缓存网关。
- 事实边界：项目已使用 String、TTL、缓存、锁、Lua、请求合并和故障降级；其他数据结构、RDB／AOF 与淘汰策略属于面试知识准备，不宣称项目实现过。行情缓存不等于已经实现业务数据库缓存一致性。
- 用途比较：Redis 共享 Session、ZSet 排行榜等属于知识准备，用于理解数据结构与选型；本项目无状态认证和只读行情缓存不因此增加这些产品功能。
- 深度：能设计 Key／TTL、说明竞争与缓存失败的处理；不读 Redis 源码，不讲复杂集群运维。

#### 8. HTTP、REST 与外部接口

- 必教：DNS、TCP／UDP 区别、TCP 连接建立／关闭、长连接与连接复用；HTTP／HTTPS 与 TLS 基本流程、请求方法／状态码、RESTful API、CORS；接口幂等、统一错误模型；超时、有限重试、限速、并发上限与降级；JSON-RPC 与第三方 API 适配。JSON 概念承接第 1 块，身份机制承接第 6 块，Provider／Adapter 的实际应用承接第 1 块的模式原理，不重复开课。
- 案例：前端 → Spring Boot API → Longbridge；结合 [Result](../../src/main/java/com/stock/system/common/api/Result.java)、ErrorCode 和异常处理解释失败转换。区分单位时间请求数与同时在途请求数；幂等按具体业务与重试后果判断，不能由 HTTP 方法名推断所有接口已有幂等保障。
- 基础比较：同步 HTTP／RPC 与 MQ 异步消息、生产／消费、重复消费与幂等、确认与重试；SSE 随 V2 流式实现学习，WebSocket 先理解适用差别。MQ 当前未接入，掌握一种并完成真实异步场景仍按后续阶段推进。
- 深度：能描述请求契约、失败与有限重试、替代数据路径；Longbridge 只是第三方接入案例，不单独作为一门课程。

#### 9. 测试与工程化

- 必教：Maven 依赖与构建生命周期；Git 实际工作流；环境变量／配置与密钥隔离，Profile 原理承接第 3 块；SLF4J／Logback／日志级别；JUnit Jupiter、Mockito、MockMvc；单元／集成测试；真实 MySQL／Redis 集成与并发测试；前后端测试边界；测试数据与本轮进程清理；Linux／Shell 基础，进程、端口、文件权限与日志排错，可复现构建、启动及 Docker／Nginx 基本交付。
- 案例：已有模块的正常、异常、权限与竞争用例，以及配置切换、依赖排查和故障日志；测试执行和清理只见 [测试规则](../engineering/testing.md)。基础日志已存在，请求追踪与完整观测平台仍按技术栈状态判断。
- AI 辅助研发：按 [岗位分流与学习优先级](#岗位分流与学习优先级) 的质量闭环检查生成代码／SQL，区分需求拆解、本人决策、AI 产出与验证结果；工程表达承接 [PROJECT-02](../career/interview/01-project-engineering.md#project-02ai生成代码后如何保证质量)。
- 深度：能独立设计用例、运行并判断证据覆盖，能用日志、异常堆栈和环境检查定位常见故障；不背 Git／Linux 命令大全，不用覆盖率数字代替质量，不展开高级运维。

### V2 功能与学习地图

2026-10-09 用户要求先形成全貌，不立即进入调用、参数或代码细节。地图分别说明产品功能、学习范围与深度、开发／学习顺序和学习方式；后面的详细规格在对应阶段使用，不要求先理解所有技术名词。

#### 产品做出的功能

既有 Java 系统继续负责用户、空间、股票、观点、数据与权限；新增研究助手负责围绕这些资料进行整理、问答和追问。用户在现有单股研究页使用同一个助手，产品方向与访问边界只见 [V2 需求](../product/requirements-v2.md)。

| 功能 | 用户能做什么 |
| --- | --- |
| 研究梳理 | 点击按钮，看到最新可用报价、成员看法、判断变化和待核对事项 |
| 行情与财务问答 | 询问报价、有限期间的价格变化、已覆盖财务指标和可比变化，得到来源、时间及口径 |
| 公司报告问答 | 询问已入库报告中的业务说明、管理层解释和风险，得到相关段落依据；这是必做 RAG 功能 |
| 连续追问与个人对话 | 围绕当前研究继续问，离开后能恢复自己的聊天，主动清空，切换对象不串资料 |
| 查看依据与缺口 | 打开观点、数据快照或报告段落；无资料、无权限或不能支持结论时有明确反馈 |

报告库由系统维护、脚本导入，普通用户不用上传或建库。能回答的范围由实际数据覆盖和当前权限决定。另完成至少一个 MCP Server 的学习实践，让标准客户端实际发现并调用受控工具；通达信／Wind 接入、观察条件核对和空间变化简报继续保留在后续方向。

#### 学什么、学多少与学到什么程度

核心学习量按八组主题组织：做一个 Java 业务 Agent 闭环，实际掌握一种 Java AI 框架、一种向量库，并实现或接入至少一个 MCP Server。八组是能力覆盖分组，授课依赖顺序与本人模块以下文为准；框架随模型、工具、会话与检索的实现学习，不另开一门要先学完全部组件的课程。技术名称、组件和完整原始目标的对应只见 [能力覆盖表](../architecture/technology-stack.md#原始-agent-目标覆盖与验收)，以下是初学者的理解与练习地图。

| 学习主题 | 这组知识解决什么 | 本项目的掌握标准 |
| --- | --- | --- |
| 模型基础与资料组织 | 知道模型怎样生成回答、能力局限，以及回答时需要哪些资料 | 能解释为何会编造、为什么需要外部资料，区分资料检索与训练模型；知道 Token／上下文、Embedding 和 Attention 的作用；能修改模型输入检查效果。原理达到解释层，不要求训练或数学推导 |
| 工具与任务流程 | 让助手根据问题查询允许访问的数据，知道何时继续、停止或报告失败 | 能设计工具输入、查询范围、校验与停止条件，在 AI 辅助下落实并检查关键逻辑；追踪一次真实调用，判断越界或查询失败是否正确处理 |
| RAG 报告检索 | 从系统报告库找到相关内容，支持有依据的回答 | 能在 AI 辅助下串起小型报告检索问答，检查分块、过滤、检索与引用；解释失败阶段，并设计和核对一种改进的效果 |
| 会话与记忆 | 让追问保留必要上下文，正确保存、恢复、清空与隔离 | 能实现或修改关键会话逻辑，说明保存的聊天与本轮提供给模型的资料有什么关系 |
| MCP | 让工具按统一规则供客户端发现和调用 | 至少完成一个 Server 的实际接入或实现，客户端真正用到工具；能解释它与普通接口、模型选工具的关系 |
| 一种 Java AI 框架 | 用一套 Java 组件组织模型、工具、会话、报告检索和流式回答 | 主选 Spring AI，经兼容验证后实际使用；能修改配置或关键调用、定位问题，并说明框架替我们做了什么 |
| 可靠性与安全 | 处理无权限、超时、重复请求、并发、费用和资料中的诱导文字 | 能给关键请求设置边界，设计正常与失败检查，并解释为什么交给 Java 控制 |
| 评测与排错 | 判断回答是否有依据，比较修改前后效果并找出故障阶段 | 能维护带依据与评分规则的固定问题集，核对查询、检索与回答，记录耗时和费用；完成真实失败的定位、修改与复测，保留前后比较 |

岗位分流沿本文件前述规则：当前准备 Java 可用的应用工程能力；Python、学历、指定框架及平台／研究要求分别核对。Spring AI 是主项目选型，不是本轮岗位统一点名的框架。框架和协议用来承载上面的链路能力，不以调用名数量验收。

每个业务模块从可核对的输入和正常／缺资料／失败例子开始，逐步形成固定问题集；评测、来源权限和基本轨迹贯穿开发，不等最后一段才第一次检查。正式 RAG 仍须对照关键词／向量／混合检索和一次重排，MCP 仍须真实发现并调用一个受控工具。功能证据由 tasks 保存，个人证据维度按 teaching 由 status 保存。

重点深度是能解释关键链路、判断设计、审阅实现和验证效果，尤其是工具、RAG、会话和质量判断。框架、向量库与 MCP 要实际使用并能排错；本人独立编写或修改逻辑另按编码目标核对，只听概念或让 AI 全部代判断不满足工程应用目标。完整框架源码、复杂平台和算法研究不作为本版完成条件。长期记忆、模型路由等扩展先理解作用；高级规划、Multi-Agent、Graph RAG 按原目标后学。基础 Python 随脚本／必要适配练习，Java 保持主语言；脚本基础不等于满足 Python 主语言应用岗，若后来明确投这类岗位，再补独立 Python Web／API 实现能力。Skills／Harness 先对应任务组织、运行控制与评测理解，不为名字另建平台。

#### 做的顺序与学的顺序

开发顺序以能逐步使用的产品结果为单位；学习顺序以理解依赖为单位。先把全貌讲清，再学习模型与资料的基础，然后在做页面和工具时掌握一套框架，继续学会话、RAG、MCP，最后综合回顾和排错。无需先上完八组理论再开始动手；安全、费用、测试和评测穿插每段。

| 开发段 | 要交付的结果 | 详细任务对应 |
| --- | --- | --- |
| 1. 提前验证关键条件 | 分别确认模型、财务资料、报告检索和框架有可检查的实现路径 | AG-CODE-001／001F／001R／002 的提前验证 |
| 2. 第一张真实页面 | 当前研究周期可梳理真实观点，带报价与依据；有最小个人会话保存和失败反馈 | AG-CODE-002／003／004 |
| 3. 数据查询与追问 | 实际完成观点、报价、有界日 K 和核心财务问答，来源及数字可核对 | AG-CODE-005／005F；工具边界沿 003 |
| 4. 完整会话与交互 | 返回可续聊，清空与权限变化有效，流式显示有结束／失败状态，迟到结果不串对象 | AG-CODE-006／007；会话基础沿 004 |
| 5. 报告 RAG 接入 | 同一助手能检索报告、回答并查看段落，资料导入、更新和移除可核对 | 提前 AG-CODE-001R，正式 AG-CODE-008 |
| 6. MCP 实践 | 一个客户端真实发现并调用受控工具，授权失败和故障可处理 | AG-CODE-009 |
| 7. 整体收口 | 固定问题集、浏览器回归、费用与故障核对、演示及项目表达 | AG-CODE-007／008／009 的整体核对，交付沿阶段 7 |

以上分组不代表七次对话或固定工期，整体难度仍为中等偏高，主要在资料、权限、上下文与回答质量。前置验证和学习理解各自记录，不能因 AI 已跑通程序就判断学生已经掌握。

#### 怎样学与完成标准

共用执行方法与证据判据只见 [教学方法](teaching.md)。本节保留 V2 时间预算、模块顺序与具体产出；兼容、框架／页面接线、测试环境和资料条件由 AI 处理。

约 45 分钟仅作为较大完整业务模块的参考学习预算；短专题讲到目标深度即可结束，不为凑时间扩展示范／练习，不固定划分各环节时长。较大模块按不同业务结果拆分，不按辅助方法或字段拆课；卡点、检查与推进方式统一沿 teaching。时间预算不代表固定时间学会，实际个人证据另记。

V2 第一轮能力模块按下表安排，框架学习、安全、费用、测试与面试表达穿插其中，不另外开框架全组件课程。模块与开发段不严格一一对应，前置数据／框架预检由 AI 提前完成，个人练习只在已可解释、可验证的正式功能范围内进行。

| 模块 | 项目里的完整问题 | 本人要形成的产出 | 复用 V1 能力 |
| --- | --- | --- | --- |
| 1. 模型调用与资料组织 | 已授权的周期资料和问题怎样组成消息，通过 ChatClient 取得回答 | 提出输入／System Prompt 规则，审阅落点，核对资料完整与缺失时的回答边界；说明调用与输出 | 复用资料 Service，理解权限、范围与失败；不重新讲 SQL 接线 |
| 2. 结构化输出与依据校验 | 回答怎样转换为页面所需对象，引用怎样对应实际读取资料 | 区分格式合法与依据正确，识别无效引用；提出校验／失败规则并核对实现 | DTO／JSON、集合、参数校验、异常 |
| 3. 受限工具与追问 | 模型提出查询，Java 校验、执行回传并停止；行情／财务按真实覆盖使用 | 设计一项受限工具的查询／校验边界，审阅关键实现，解释合法／越界／空结果轨迹 | Service、外部 API、缓存、故障降级 |
| 4. 个人会话与状态 | 保存与恢复自己的有效上下文，切对象、清空和失权不串资料 | 分析一个状态变化，提出保存／失效规则并核对正常和竞态结果 | 表关系、事务、权限与并发状态 |
| 5. 失败、流式与质量 | 超时／重复请求／预算／中断怎样结束，回答是否有依据 | 定位一个失败并提出修正，审阅修改和复测；维护一组有依据的问题对照 | JUnit／Mockito、日志、幂等与错误处理 |
| 6. 报告 RAG | 报告导入、分块、向量化、过滤检索、依据回答与资料版本 | 根据坏例子选择一种检索改进，审阅改动并比较命中和引用；检查小型链路各环节 | 数据状态、批处理、SQL／索引、测试 |
| 7. MCP 与综合表达 | 标准客户端发现并调用同一受限 Service | 完成一次合法调用与拒绝验证，解释身份、工具与业务层关系 | API 契约、认证、范围与故障定位 |

第一轮从模块 1 起步，当前单元与本人下一动作只见 [学习交接](status.md#求职专题学习交接)，不因方法调整重置进度。第一单元围绕“授权资料＋问题→模型消息→ChatClient 调用→回答与依据核对”，本人参与输入／回答要求和结果判断；资料 Service 沿 AG-CODE-003 复用。一次 Prompt 示例不能关闭完整框架／工具／RAG 目标。

视频选择沿 [实习准备与阶段关系](#实习准备与阶段关系)。本阶段先暂停新增视频和整套重看，用上述业务任务暴露具体缺口；需要补课时由 AI 给出相关片段、理由和要回到项目完成的动作，不让学生自行选专题或阅读迁移文档。个人观看进度只见 status；课程与版本差异仅见 [课程研究记录](java-agent-market-benchmark.md#6-课程核查与选学建议2026-10-09)。

Agent 与既有 Java 专题并行，不以学完 JUC／JVM、独立写完整接口或完成所有 Java 专题作为入门条件；并发、事务、缓存和 JVM 继续沿原路线。概念复习见 [模型、Java 与工具的数据流](../engineering/agent-experiment.md#11-先分清模型java-和工具)，基础补讲与参与方式只由 teaching 维护。

本版个人产出按上表检查：能解释 Java 与模型职责，针对新问题提出有权资料和处理规则，在 AI 辅助下审查工具／会话／检索实现，核对依据与真实轨迹，定位并复测一个错误；通过前后评测和短演示讲清选择、数据路径及边界。另在明确的编码练习中逐步验证能否独立修改工具／检索关键逻辑，不由 AI 产出代填。简历使用实际覆盖、次数和测量结果，没有真实流量时注明小范围验证。

这些是学习产出，不是企业统一录用线，也不保证固定工期。真实框架、工具、RAG 和 MCP 的实施目标保持，个人能力按 teaching 分维度记录。

第 1 段的模型、财务、RAG 和框架验证需要各自取得独立证据，不能相互替代。财务源 AG-CODE-001F、报告解析与中文检索 AG-CODE-001R 要在主业务大量投入前提前验证；主框架兼容在隔离环境验证后再改主项目。兼容未通过时用现有直接 Java HTTP 路径保留实验和阶段成果，框架实践仍需另验。正式 RAG 页面在第 5 段接入，不表示到那时才第一次检查报告能否读取。验证方法和失败替代只见 [技术规划](../architecture/technology-stack.md#34-可行性验证与知识安排)。

技术主线沿用 Java、Spring Boot、现有数据库与 Vue，模型使用用户选定的官方 DeepSeek；Java AI 框架主选 Spring AI，必须实际使用并验证兼容。RAG 另需文本向量模型和一个向量库，Qdrant 是待验证候选；会聊天的模型调用成功不证明这些已具备。具体版本和采用状态只维护在技术栈，不要求用户预先选择内部参数。基础 Python 随评测／适配练习；原 Java 基础、SQL、Redis、真实异步 MQ 等路线继续保留，不强行成为第一个助手页面的依赖。

从最早调用起落实权限、参数和引用校验、输入范围、超时、有限调用、基础用量与失败样例，再逐段加深；第 7 段负责整体收口，不能将这些保护推迟到最后。初次梳理是 Java 先读取所需资料的固定流程，追问才验证模型按需选工具；前者成功不能代替后者。网页主链路关闭 Agent 后仍要保留 V1 的正常业务。

### 后续需求在地图中的位置

观察条件核对、空间变化简报与通达信／Wind 接入期望继续保留，范围与先后沿 [产品后续方向](../product/requirements-v2.md#32-后续需求方向与外部数据期望)。建议先做已有数据能核对的明确条件、用户主动生成的有限空间简报；外部数据先验证一个有授权的只读查询。它们不挤入首次页面，也不因在地图中出现而标为已接入或已确认全部细节。

自动荐股和自动交易不进入本版。总图之后按上述学习顺序从基础概念推进，具体技术问题随对应实验落实；涉及新账号、预算或生产开放的决定在启用前说明具体方案，不让它们阻塞概念教学。

验收时须证明工具调用和最终回答可以追踪，关键问题有稳定测试集，失败时不会写入错误业务数据；权限与工具范围以 [V2 需求](../product/requirements-v2.md#2-已确认范围与边界) 为准，学习覆盖逐项沿 [原始 Agent 目标对照](../architecture/technology-stack.md#原始-agent-目标覆盖与验收) 核对，阶段成果不代替未完成的 RAG／MCP／框架实践。
