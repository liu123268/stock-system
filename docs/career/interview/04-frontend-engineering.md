# 前端工程面试问答

## FRONTEND-01：Vite前端为什么需要单独启动？

### 完整回答

> Vue 单文件组件和 TypeScript 源代码需要由 Vite 在开发阶段完成模块转换、依赖处理、热更新和页面服务。`npm.cmd run dev` 启动的是持续运行的开发服务器，不是每改一次代码都重新执行一次。生产环境会先构建为静态文件，再由 Nginx 等静态服务器提供，不使用 Vite 开发服务器。

## FRONTEND-02：Element Plus按需导入做了什么优化？

### 完整回答

> 项目最初全量注册 Element Plus 时，生产构建曾出现大包警告。认证页面实际只使用表单、输入框、图标和消息提示，因此改为组件和样式按需引入，并结合 Vue Router 动态导入进行路由级代码分割。认证阶段曾记录包体积下降；历史数字与原理见 [前端教学](../../engineering/frontend.md#三element-plus按需导入)，不作为当前版本构建结果。

## FRONTEND-03：如何让前端视觉持续迭代而不失控？

### 完整回答

> 项目没有逐页复制视觉参考，而是把近黑白色彩、字号、间距、圆角、焦点状态和动效边界提炼到 `docs/architecture/ui-design-system.md` 与共享样式。公开首页负责品牌表达，认证页使用左侧轨道视觉区和右侧稳定操作区，业务工作台继续降低装饰强度。正式页面不使用鼠标跟随背景、黑色等高线或持续跳动视频，并支持 `prefers-reduced-motion`。视觉重构保持 Store、API 和测试选择器稳定，通过类型检查、静态检查、单元测试、生产构建和真实浏览器视口验收，避免审美调整破坏业务数据流。

## FRONTEND-04：为什么生成邀请码成功后还要特别处理刷新失败？

### 完整回答

> 生成邀请码的 POST 成功，说明数据库状态已经改变；随后刷新邀请历史只是读取最新展示数据。如果把两步放在同一个 `try` 中统一抛错，历史 GET 的网络失败会让页面提示“生成失败”，但事实上新邀请码已经生效，用户再次点击还可能触发并发前置条件冲突。项目因此先保存 POST 返回的新邀请码，再尝试刷新历史；刷新失败只保留局部错误和重试能力。停用也类似：DELETE 成功后先清空当前代码，不能因为历史读取失败继续展示已经失效的凭证。

### 项目证据

- `workspace Store` 的 `generateInvitation` 与 `stopInvitation`；
- 邀请区域独立的 loading、error 和 action message；UI-05 还以 `Promise.allSettled` 保留当前邀请码／历史各自成功的读取结果，失败部分保留 GET 重试，详见 [概览数据流](../../engineering/frontend.md#ui-05-中的独立读取与邀请生命周期)；
- Store 单元测试与双账号真实浏览器闭环；UI-06 将同一原则用于移除／转让／退出：保存后 GET 失败不显示事务失败，结果保留并只读重试，见 [成员与设置数据流](../../engineering/frontend.md#ui-06-中的保存结果与页面归属)。

## FRONTEND-05：前端为什么不能把所有 API 失败都当成“退出登录”？

### 完整回答

> 失败原因代表不同状态。工作台页面处理空间 API 失败时，HTTP 401 会清除 JWT、当前用户和全部空间缓存并返回登录页；`WORKSPACE_MEMBERSHIP_INACTIVE` 或 `WORKSPACE_NOT_FOUND` 只说明当前空间不可访问，应保留账号会话，清除当前空间并返回选择页；普通网络失败不能证明权限变化，所以保留页面和会话并允许重试。这部分用 `ApiError.code/status` 分流，不能扩大成所有认证入口都已经采用相同处理；路由守卫的 `/api/auth/me` 失败处理边界见 [认证设计](../../architecture/authentication.md)。

### 项目证据

- `utils/workspace-access.ts` 的错误分类；
- 概览、成员和设置页复用同一处理入口；
- 单元测试分别验证 401 与成员关系失效；
- 退出登录使用 `clearAll()`，切换空间使用 `clearCurrent()`，两者不会改变后端成员关系。

## FRONTEND-06：为什么类型检查通过，数字表单仍可能在浏览器报错？

### 完整回答

> TypeScript 检查的是源码声明，Vue 表单绑定还会受到 DOM 输入类型和运行时转换影响。共享自选表单最初把目标价声明成字符串，并直接调用 `trim()`；但 `type="number"` 的 `v-model` 在真实交互中给出了数字，因而浏览器提交时报错。修复不是强行断言类型，而是让边界转换函数明确接受字符串或数字：空字符串转为 `null`，其他值用 `Number` 转换并验证为正数。Store 和 API 继续只接收已经规范化的 `number | null`。这说明类型检查能减少错误，但浏览器 E2E 仍负责验证框架、DOM 与业务代码真正组合后的行为。

### 项目证据

- `WorkspaceStocksView.vue` 的可选价格规范化；
- 股票 Store 单元测试和 TypeScript 检查；
- 双账号 Chrome 流程实际填写目标价、止损价并完成提交；
- 桌面与手机视口截图验收。

## FRONTEND-07：怎样优化页面重复请求而不削弱权限校验？

### 完整回答

> 我先用隔离浏览器记录页面切换请求链，再绕过页面重复测后端接口。后端接口稳定，但前端每次切换都会重复调用 `/api/auth/me` 和空间详情，并串行等待页面业务数据。优化时没有删除后端鉴权，而是在 Pinia 中区分“localStorage 恢复的未确认会话”和“本次运行已由后端确认的会话”，同时用 `ensureCurrent(workspaceId)` 只复用同一空间的运行期详情。刷新页面、换空间、退出登录、401 或成员关系失效仍会重新走真实校验。隔离浏览器复测中，共享自选和成员页分别从 3 个请求降为 1 个，设置页从 2 个降为 0 个；业务接口本身仍逐次验证 JWT 和空间成员关系。

### 当前边界

上述请求数是当时优化阶段的历史证据，不能当作 UI 迁移后的当前请求数。当前成员、设置等治理入口每次进入重新读取空间身份，成员页并行读取成员列表，以承接另一会话改变的 OWNER／归档状态；`ensureCurrent` 只在调用它的页面复用运行期详情。原优化证明请求链可缩短，不代表真实 Longbridge 行情回源速度；开发模式耗时还会受到 Vite 首次转换和本机调度影响。

## FRONTEND-08：为什么加了读取版本，切股票后仍可能显示旧数据？

### 完整回答

> 读取版本能阻止旧 GET 回填，但旧 POST 也可能在切到股票 B 之后才返回，再启动股票 A 的 GET；这个新发出的读取反而具有最新版本。项目因此分别保护写入回调与读取回调，并在页面换参数或卸载时使旧目标失效。页面每个 await 后也检查业务 ID 和版本，避免旧时间线完成后把提示带到 B。草稿与结束确认进一步绑定研究周期 ID，别人结束并重开后需重新确认。前端失效只停止后续显示与刷新，不能撤销服务器已成功的事务。
